## 懸念事項（複数視点）

- **止める設計の安全性は、遷移の表にかかる**: 許す組の漏れを検知できるのは、状態遷移図ではなく許す組の表から作った状態遷移テストだけ。スケッチを基準に生成器を作ると、漏れを見逃す（TS、AR、UR）。
- **新しいコードはすべて型検査していない**: `Tx.run`、`Resource` のロック、`Committed` は未検査（K3・K6・K10）。B1 の最初のスライドで型を確定してから、後続の振る舞いのテストを先に書く順序が必要（TS、AR）。
- **Kotlin 版で未承認の判断の上に積んでいる**: 引き継ぐ行の多く（003〜011・013・014・020）は Kotlin 版でも提案中。Kotlin 版の ADR のステータスが変わったとき、どう検知して追従するかの仕組みが 1 文だけ（PM）。
- **ポーリングの画面は止まったことに気づけない**: `Ignored` はコマンドの経路でだけ起きるので、GET は成功し続ける。気づくのは次に操作した人だけ（UX）。
- **承認が要る文書が多い**: 依頼文言、研修中の原則、パターン 18、Intent の文面はすべて AI の案で、運営者との合意（未決事項 3a）の前に研修で使わない（UR、PM）。

## スコープ外の発見（正本・共有物の側）

- Kotlin 版 ADR-017・019 は、ステータス節は「承認済み」だが、タイトルと決定の見出しは「提案」、冒頭は「ADR としては提案中のまま」で自己矛盾している。Scala 版 ADR-001 はステータス節を根拠に承認済みと数えている（PM）。
- Kotlin 版 ADR-004 の「実 DB の並行（同時の 2 要求）での検証は未実施」を、Scala 版の B1 の「並行時の制約名」の行で同時に確かめる（PM）。
- Kotlin 版の `domain-model` の EV-S07 と EV-S10 の重複は、正本側の整理が要る。同じ写しの漏れ（`ObserverInvitationRevoked`）が Rust 版にもないか、正本の遷移表と突き合わせる価値がある（AR）。
- 共有の画面の課題（全実装共通）: S06（進行役のコンソール）には自動更新も手動更新のボタンもない。`apps/beer-game-web/package.json` の `description` が「（Kotlin 版）」のまま（UX、UR）。
- Kotlin 版の `test-strategy.md` の境界値の表は「上限ちょうど / 上限 + 1」と書き、実装（総試行回数）と言葉が違う（TS）。
