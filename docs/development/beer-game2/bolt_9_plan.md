### ゴール

進行役が、終了済みのゲームの全記録（設定と「カスタム」の別、全週・全役割の値、意思決定、費用、履歴）を CSV と JSON で出力できる。両形式の数量と費用は一致し、スキーマ版を記録する。出力が完成しなければ、部分的な結果を返さない。

### 確認したい仮説

1. **出力が、完全かつ再利用できるか**（[リリース計画](./release_plan.md)の仮説）。役割別の週結果の行とイベントから、CSV と JSON の両方を同じ純粋関数で組み立てれば、両形式は必ず一致し、欠けた行は組み立ての時点で検出できるか。

### 対象の受入条件（原文）

| ID      | Given / When / Then（原文）                                                                                                 |
| :------ | :-------------------------------------------------------------------------------------------------------------------------- |
| AC4.3.1 | 終了済みのゲームで CSV と JSON を出力すると、設定（「カスタム」の別を含む）・全週・全役割・意思決定・費用・履歴を識別できる |
| AC4.3.2 | 同じゲームで両形式を比較すると、数量と費用が一致し、スキーマ版が記録される                                                  |
| AC4.3.3 | 出力の一部が失敗して処理を完了できないと、部分的な結果を完全な出力として示さない                                            |

期待値の解釈:

- 「意思決定」は、週・役割ごとの確定した発注（生産要請）と、入力の記録（参加者の保存か、進行役の代理入力か、時刻）。参加者の表示名は含めない。
- 「履歴」は、ゲームの出来事（作成、開始、確定、停止・再開、確定方式の変更、終了）の種類と時刻。資格に関わる出来事は含めない。
