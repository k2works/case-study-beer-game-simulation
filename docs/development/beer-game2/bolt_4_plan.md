### ゴール

進行役が、セッションを**停止 → 代理入力 → 再開**でき、代理入力の値が監査の記録（イベント）に残る。参加者と進行役は、ブラウザの Cookie を失っても**復帰コード**で同じ画面に戻れる。すべての資格に**有効期限と失効**があり、進行役は漏れた資格を失効させて再発行できる。鍵は複数の版を持ち、ローテーション後も旧版の資格を期限まで検証できる。

### 確認したい仮説

1. **資格の設計は、漏洩時に被害を止められるか**（[リリース計画](./release_plan.md)の仮説）。失効・再発行で、漏れた資格（ブラウザセッション・復帰コードの両方）が即座に使えなくなるか。
2. 有効期限の判定を、注入できる時計で境界（期限の直前・直後）までテストできるか。
3. 停止中の拒否と代理入力を、`Session` 集約の状態遷移として単純に表せるか。

| AC3.2.2 | 無効または削除済みの資格で再接続すると、復帰せず、進行役への確認方法を示す                     |
| AC3.2.3 | 複数のタブで一方が週を確定すると、他方は古い応答を適用せず、最新の状態を反映する               |
| AC3.2.4 | 進行役が画面を再読み込みまたはブラウザを再起動しても、資格で同じゲームの進行コンソールへ戻れる |
| AC3.2.5 | 資格には有効期限があり、進行役は、漏れた資格を失効させて再発行できる                           |

期待値の解釈（Step 1 で確定）:

- AC3.1.1 の「新規の確定」は、参加者の**発注の保存**と読む（参加者は週を確定しない）。停止中の保存は 422 で拒否し、保存済みの入力は残る。進行役の週の確定も、停止中は拒否する。
- AC3.1.2 は、`ProxyDecisionSubmitted` イベントに、操作者（進行役）・役割・時刻・数量を含める。代理入力は停止中・進行中のどちらでもできる。
- AC3.2.3 は B1 で達成済み（版による楽観的排他と、SSE による再取得）。回帰テストで確認する。

## ステップ計画

### Step 1: 受入条件の期待値を確定する（🔵）

上の「期待値の解釈」をテストの期待値にする。

### Step 2: 停止・再開・代理入力（ドメイン）（🔴🟢🟡）

- `Session.status` に `PAUSED`。`pauseSession`・`resumeSession` は進行役だけ。
- 停止中の `saveDecision` と `commitWeek` を拒否する（保存済みの入力は残る）。
- `proxyDecision`: 進行役だけ。版の一致を要求し、`ProxyDecisionSubmitted`（役割・数量・操作者・時刻）を出す。

### Step 3: 資格の有効性と鍵の版（🔴🟢🟡）

- `CredentialPolicy` が、検証用に**すべての鍵の版のダイジェスト**を返す。発行は最新の版。
- 資格の検索は時計の時刻を受け取り、期限切れ・失効を除く。
- 設定: 複数の鍵の読み込み、形式の誤りと本番での未設定を起動の失敗にする。

### Step 4: 復帰と、失効・再発行（ユースケース）（🔴🟢🟡）

- 参加・作成で復帰コードを発行する。`recover` で新しいブラウザセッションを発行し、`ParticipationRecovered` を記録する。
- 無効な復帰コードは 401 と、進行役への確認方法を示す文言。
- `reissueCredential`: 進行役だけ。対象のブラウザセッションと復帰コードを失効させ、新しい復帰コードを返す。`CredentialRevoked`・`CredentialReissued` を記録する。

### Step 5: 永続化とマイグレーション 003（🔴🟢）

メモリ版と PostgreSQL 版を同じ契約でテストする。期限・失効の境界を、DB の時刻ではなく渡した時刻で判定する。

### Step 6: HTTP とレート制限（🔴🟢）

`POST /api/games/:id/{pause,resume}`、`PUT /api/games/:id/proxy-decision`、`POST /api/recover`、`POST /api/games/:id/credentials/reissue`。参加・復帰の専用のレート制限（429）。

### Step 7: UI（🔴🟢🟡）

- 参加・復帰の画面（S03）に、復帰コードでの復帰を加える。参加・作成の直後に復帰コードを一度だけ表示する。
- 進行役のコンソール（S06）に、停止・再開、代理入力、資格の再発行（確認ダイアログつき）。
- プレイ（S05）に、停止中の表示と入力の無効化。

### Step 8: E2E と検証（✅）

停止 → 代理入力 → 再開 → 確定の流れと、Cookie を消してからの復帰を E2E で通す。`npm run verify` 相当（format、lint、typecheck、カバレッジ、受入条件の対応表、E2E）。

### デモ項目

1. 進行役が停止すると、参加者の画面が「停止中」になり、保存できない。
2. 進行役が不在の役割を代理入力し、再開して確定する。イベントに値が残る。
3. 参加者が Cookie を消して、復帰コードで同じ役割の画面に戻る。
4. 進行役が参加者の資格を再発行すると、古い Cookie と古い復帰コードが使えなくなる。
