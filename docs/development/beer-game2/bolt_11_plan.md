### ゴール

アプリが、応答時間・エラー・確定の競合・確定の方式・SSE の接続数・削除の失敗を、CloudWatch の Embedded Metric Format（EMF）で出力する。Terraform に、アラーム（API の p95、5xx、不変条件の違反、削除の恒久的な失敗）、合成監視（1 分ごと）、ダッシュボード、通知（SNS）を定義する。

### 確認したい仮説

1. **研修中の停止を 1 分以内に検知できるか**（[リリース計画](./release_plan.md)の仮説）。合成監視（1 分ごと）と、連続 1 回の失敗で発報するアラームの定義で、検知までが 1 分以内になる構成を作れるか。**実際の発報は、AWS に適用しないため確かめられない**。

### 対象の受入条件（原文）

| ID      | Given / When / Then（原文）                                                                    |
| :------ | :--------------------------------------------------------------------------------------------- |
| AC6.1.3 | 応答時間、エラー率、確定の競合、アウトボックスの遅延、SSE の接続数が、メトリクスとして得られる |
| AC6.1.5 | 研修中に、主要な操作が 1 分間成功しないと、通知される                                          |
| AC6.1.6 | 週結果の重複や、不変条件の違反が起きると、通知される                                           |

期待値の解釈:

- 「アウトボックスの遅延」は、v2 にアウトボックスが無い（[ADR-006](../../adr/beer-game2/006-sse-version-only.md)。通知は `LISTEN/NOTIFY`）ため、**状態の変化の通知から SSE への送出までの遅延**と読み替える。
- AC6.1.5・6.1.6 の「通知される」は、この Bolt では**アラームと通知の定義（Terraform）とメトリクスの出力**までを満たし、実際の発報の確認は AWS への適用後とする。
- 「不変条件の違反」は、週の確定で主キーの重複（`week_results`）や版の競合が DB で検出された場合と、予期しないエラー（500）。
