## 学び

- **項目単位の検査**: 本文の部分文字列の検索は、ランダムな ID で偶発的に一致して不安定になる。「この値がどの項目にも無い」は、構造を平らにして確かめる。変異（検査の対象を変える）で、検査が働くことを確かめる。
- **並行の試験は、待ち合わせで状況を確実に作る**: 「競合が起きるはず」を確率に頼らず、追記の直前で待ち合わせて、毎回ちょうど 1 回の競合を作る。勝者は決まらないので、両方の順で成り立つ不変条件を確かめる。
- **生成の副作用**: Gradle の計測（Kover）は、`Test` 型の task をすべて先に実行する。ドキュメントを書き換える task は、計測の対象から外す。
- **人の検証が要る点を、AI の自己申告に頼らない**: 8.4b の試験が最初から緑だったことも、Red を観察していないことも、そのまま記録した。
