| DS-10 テスト名の接頭辞（RT1）の検査 | 達成 | `crates/guards/tests/naming.rs`。AC・US の ID か分類の接頭辞（`ds`・`nf_`・`adr_`・`rb2__`・`execute__`・`evolve__`・`replay__`・`tech__` ほか）で始まらないテストがあれば失敗。規則に合わない 22 件に `tech__` を付けた。**接頭辞の検査そのものも、ユニットテストで固定** |

## 実施していない項目（承認待ち）

1. **契約テスト**（API の応答を `openapi.yaml` のスキーマで検査し、仕様と実装をずらすと CI が落ちる）: 検査には **JSON スキーマの検証と YAML の読み込みの新規クレート**（`jsonschema`・YAML パーサー）が要る。技術スタックでは候補で、**導入の承認がない**。承認があれば導入する（B2 の HTTP 越しのテストが、契約との食い違いを多数見つけたことは、導入の根拠）。
2. **git の hook・Claude Code の hook・CI の必須ジョブ（ブランチ保護）**: 開発戦略の未決事項 7・8（共有の `.claude/settings.json` の変更を含む）。**承認がない**ため新設していない。CI は最終の権威として、検査をすべて実行している。
3. **DS-15（新規依存の承認の記録の検査）・DS-17（緩和の ADR の検査）・DS-18（生成物の差分）・DS-21（`verified` の再確認）・DS-22**: hook と同じく、承認の記録を機械で検査する方式の妥当性（開発戦略の未決 8）の判断待ち。
4. **テンプレート DB による分離**: 現状のテストごとのコンテナで、問題が出ていない（約 5 秒/テスト）ため、実施していない。テストが増えて遅くなったら導入する。

## 人の判断が要る項目

1. 契約テストのクレート（`jsonschema`、YAML パーサー）の導入。
2. hook・必須ジョブ・承認の記録の機械検査の可否（上の 2・3）。
3. CI の実行時間（キャッシュの効果の確認後に、目標を決める）。
