## 簡略化と未達（人の判断が要る項目）

1. 上記の承認の扱い（個別の計画書を示していない）。
2. 並行テストは同一プロセス内（別プロセスは未実施）。
3. 自動確定の失敗の扱い: 確定は `decide` の中の純粋な計算なので、失敗の経路は無い（入力がそろっていれば必ず確定できる）。
4. `SetCommitMode` を、変わらない方式への変更では何も追記しない（版を進めない）。
5. TDD の順序: ドメインのテストと実装を同じ作業の中で書いた（B8 と同じ）。受け入れのステップは実装の後に書いて通った。
6. UI の `auto-commit-ui.feature` は、Rust のバックエンドで通った数に含まれる（22/27 の増分）。

## 発見
