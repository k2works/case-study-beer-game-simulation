## 契約テストが見つけた逸脱

- `Lobby.observers[]` の `joinedAt`（契約は必須）が、無かった。`joined_at` を返すようにした（`invitationId` は契約に無いので外した）。

## 簡略化と未達（人の判断が要る項目）

1. **DB ロールの強制はしていない**。契約は「観察画面は `beergame_observer` が読める 3 表だけから作る」と書く。実装は、その 3 表（`game_overview`・`session_overview`・`week_team_totals`）と、公開範囲だけ `game_settings` を読む。**ロールの切り替え（`SET ROLE`）や接続プールの分離、`current_user` の検査は未実施**（ログイン用ユーザーが無い。リリース計画は B15 の本番の定義で扱う想定）。DDL・GRANT の変更は無い。
2. **招待の発行は冪等記録を保存しない**（`Idempotency-Key` を受けるが、再送には別の招待を発行する。招待コードの秘密を含むため、暗号化した記録が要る）。
3. **観察者の復帰は未実装**（契約どおり、復帰資格を発行しない。設計の未決）。
4. 観察者の表示名は `display_profiles`（`actor_kind = 'OBSERVER'`）に保存し、ロビーにだけ出す。
5. TDD の順序: B8・B9 と同じ（ドメイン・ステップを実装と同時に書き、先に失敗を確認していない）。人が判断。
6. `@ui` の観察者の画面は、`web/` の `observer-ui.feature` が、今の Rust のバックエンドでは通らない分がある（22/27 は B9 と同じ）。原因は未調査。
