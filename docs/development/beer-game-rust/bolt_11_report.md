## 簡略化と未達（人の判断が要る項目）

1. **出力は要求時に作る純粋な関数**（`build_csv`・`build_json`・`checksum`。application）。表は作らない（契約どおり）。全体を組み立ててから返す（ストリーミングしない）。
2. **組み立ての失敗（AC4.3.3。500 `app.internal`）は未実装**。純粋な文字列の組み立てで、失敗の経路が無い（`write!` の失敗を無くした）。本番の定義で、必要なら扱う。
3. **JSON は文字列で組み立てている**（`serde_json` を application に足さないため）。文字列の値は、固定の列挙・UUID・項目名だけで、エスケープは要らない。変更した項目の値は、コードが決める列挙。

6. TDD の順序: ステップ定義と実装を同じ作業の中で書いた（B8〜B10 と同じ）。人が判断。
