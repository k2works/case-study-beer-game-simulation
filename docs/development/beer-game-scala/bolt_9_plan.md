### ゴール

進行役が観察用の招待を発行・失効させ、観察者が招待コードで（役割なしに）参加して、公開範囲内の情報（現在週・完了状況・チーム合計）だけを観察できるようにする。観察者は、役割別の値・将来の需要・参加コード・入力者を取得できず、入力・確定・進行・資格の操作もできない。終了後は振り返りを取得できる。

### 確認したい仮説

1. 情報が漏れないか（観察の内容に、役割別の値・将来の需要・参加コードが含まれないか）。
2. 観察者を新しい種類の呼び出し元（`Caller.Observer`）として足しても、既存の認可（進行役・参加者）の否定テストが保たれるか。
3. 招待コードを、参加コードと区別して扱い、ダイジェストだけを保存できるか。

### 対象の受入条件

| 対象 | 内容 |
| :--- | :--- |
| AC1.3.1 | 進行役が観察用の招待を求めると、参加コードと別の招待コードが発行される。招待コードは参加コードとして使えない |
| AC1.3.2 | 進行役以外は招待を発行できない |
| AC1.3.3 | 観察者は役割を持たず、参加者の一覧に含まれない。ロビーに載る。入力を保存できない |
| AC1.3.4 | 招待を失効させると、新しい参加はできないが、参加済みの観察者は観察を続けられる。進行役以外は失効させられない |
| AC4.1.1 | 現在週・入力済みの役割数・確定した週のチーム合計（注文・在庫・受注残） |
| AC4.1.2 | 役割別の値・将来の需要・参加コードは返さない。観察者が他の API を呼ぶと 403 |
| AC4.1.3 | 公開範囲が「なし」なら、合計を出さず理由を示す |
| AC4.1.4・4.1.5 | 招待のない人・参加者は観察できない。観察者は入力・確定・進行・失効・割り当てができない |
| AC4.2.1 | 観察者は、終了後に振り返りを取得できる（プレイ中は開示しない） |

## 人の判断が要る項目（着手前の承認。**未承認**）

1. マイグレーション V006（`observer_invitations`。招待コードのダイジェスト・ゲーム・招待の ID。`browser_sessions` の種別の制約に `observer` を足す）（データベース。確認必須）。
2. **観察者専用の DB ロール・接続プールの分離は実装しない**。契約は「`beergame_observer` が読める 3 表だけから作る」とするが、本実装は投影表を持たず、観察の内容をイベントの再生から作るため、対応する表が無い。観察の内容は、アプリケーションが公開範囲の関数で絞る（否定テストで守る）。分離が要るかは、人が判断する。
3. 招待の有効期間は 7 日（契約の仮置き）。
4. 寄与者が 2 未満の週は値を出さない（契約。現行は常に 4 役割が寄与するため、実質動かない）。
5. 新しい code `game.invitation_not_found`（404）。観察者には復帰資格を発行しない（契約どおり）。
6. イベントには招待の ID と期限だけを入れ、招待コードの値は入れない。
