### ゴール

Release 1.0 に向けた仕上げを、**実測できる範囲で正直に**まとめる。(1) 横断のセキュリティ（全応答のセキュリティヘッダー・ログに秘密を残さない）を実装して受け入れる。(2) 共有の画面（`@ui` 27 シナリオ）を Scala のバックエンドで通し、落ちるものの原因を分類する。(3) 実 PostgreSQL での性能の計測（確定から反映・出力・再生・同時の負荷）。(4) NFR の検証表と、Release 1.0 の準備状況（未承認の判断・未適用の項目の一覧）を作る。AWS には適用しない。

### 確認したい仮説

1. 非機能の目標を満たすか（満たすものと、機能が無くて測れないもの・本番でしか測れないものを、正直に切り分けられるか）。
2. 共有の画面は、Scala のバックエンドで、27 シナリオ（`@ui`）が通るか。通らないものは、API の不足か、画面側か、環境か。
3. 全応答（成功・拒否・存在しない経路）に、セキュリティヘッダーを付けられるか。ログのどこにも、資格・表示名が出ないか。

### 対象の受入条件

| 対象 | 内容 |
| :--- | :--- |
| X-3（NF-O1） | ゲームを 1 週進めたあとの構造化ログの全体に、資格・参加コード・復帰コード・参加者の表示名は含まれない |
| X-5（NF-S9） | 成功した応答にも、拒否された応答にも、存在しない経路への応答にも、CSP・HSTS・nosniff・Referrer-Policy・キャッシュ無効のヘッダーが付く |
| X-1・X-2・X-4 | 画面（`@ui`）と既存の受け入れで確かめる範囲を、NFR 検証表に記録する |
| NF-P2・P9・P18・P16 | 実 PostgreSQL での確定から反映・出力・再生・起動時間の実測 |
| ヘルプ・狭い画面・アクセシビリティ（画面） | 共有の web に実装済み。Scala のバックエンドで `@ui` を通す |

### 範囲外

SSE（自動反映）、観察者専用の DB ロール・接続プールの分離、出していない指標（研修中・競合率・ヒープ）の出力、AWS への適用・本番の設定、Edge・実機の Safari・スクリーンリーダーの確認、投影表（許可リストから外れた 8 シナリオの扱いは判断項目）。
