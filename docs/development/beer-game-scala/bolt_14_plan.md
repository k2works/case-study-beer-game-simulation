### ゴール

本番へ安全に出し、戻し、復元できる**定義**をそろえる。(1) 本番相当の起動（PostgreSQL・秘密情報は環境変数・H2 の拒否）と、起動モード（api・migrate・retention・verify）を持つ JVM のコンテナ（マルチステージ）。(2) Kotlin 版の Terraform（ネットワーク・ALB・ECS・RDS・秘密情報・独自ドメイン・ACM・TLS・セキュリティヘッダー・ブルー/グリーン・観測）を Scala 版へ適応し、`terraform validate` が通る。(3) 運用手順書（デプロイ・本番・復元・ロールバック・観測）。**AWS への適用はしない**。

### 確認したい仮説

1. 本番へ安全に出し、戻し、復元できる定義になっているか（手順と定義が一致するか）。
2. JVM の起動時間は目標に収まるか（コンテナの開始から `/ready` が 200 になるまで）。
3. H2・秘密情報なし・不正な設定では、本番相当の起動が失敗するか（誤った本番を防ぐ）。

## 人の判断が要る項目（着手前の承認。**未承認**）

1. **AWS には適用しない**（定義と `terraform validate`、ローカルのコンテナのスモークテストまで）。
2. Kotlin 版の `infra/` を Scala 版へ複製して適応する（共有モジュール化はしない。人が決める）。
3. 起動方式: `ENTRYPOINT` + 起動モード `api`（既定）・`migrate`（マイグレーションを適用して終了）・`retention`（1 回の掃引）・`verify`（整合の検査）。ローカルの `Main` は、環境変数が無ければ H2（従来どおり）。
4. 本番の設定: `APP_ENV=production` では、H2 を拒否し、秘密情報（資格の署名鍵 `BGS_CREDENTIAL_KEY`）と PostgreSQL の接続（`DB_URL`・`DB_USER`・`DB_PASSWORD`）を必須とする。不足は終了コード 78（EX_CONFIG）。
5. 削除用のロール・追記専用ロール（V003）の本番での使い分け（所有者の接続での削除は、本番では別のロールにするか）は、定義（運用手順書）に記録し、AWS 上の確認は適用前の項目とする。
6. メトリクス・アラームの定義は、`Alarms` の表（B13）に合わせる。**実行中のサーバーが出していない指標（研修中・競合率・ヒープ・合成監視）のアラームは、定義するが、指標が出るまで機能しない**ことを明記する。
7. ビルドは、新しい sbt プラグインを足さず、`build.sbt` の自作タスク（`dist`）で依存の JAR を集める。
