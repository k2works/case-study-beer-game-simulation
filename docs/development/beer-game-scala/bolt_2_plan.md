### ゴール

B1 で設定した静的解析・テストを CI で回し、規約違反と品質の劣化をマージの前に止める。CI は `check`・`integration`・`acceptance` の 3 ジョブに分け、行カバレッジのゲート（全体 80%）と、追記専用権限の否定テストを備える。

### 確認したい仮説

1. 規約違反コードで CI が落ちるか。
2. scoverage でプロジェクトごとのしきい値を設定できるか（できなければ全体のしきい値だけにする）。
3. API の契約テストが成り立つか（OpenAPI と実装のずれを検出できるか）。
4. Docker を要する統合テストを `check` から分離しても、速さと網羅を両立できるか（案 Y）。

### 対象の受入条件

| 対象 | 内容 |
| :--- | :--- |
| NF-S4・NF-S13（非機能） | 資格・秘密情報の扱い。秘密情報・依存関係の検査を CI に含める（SR13） |
| NF-C（追記専用） | イベントの書き込みロールは INSERT・SELECT だけ。UPDATE・DELETE・TRUNCATE は拒否（PostgreSQL。42501） |
| チーム規約 | 行カバレッジ 80% を floor にする。formatter・linter・type-check の失敗はマージしない |
