## 計測の条件と限界

- **環境**: 手元（macOS の Docker Desktop）の実 PostgreSQL 18.6（Testcontainers、接続プールは既定）。**インプロセスの HTTP ルーター**を呼ぶ（ネットワーク・ブラウザ・SSE・複数タスクを含まない）。AWS（Fargate・RDS）の値ではない。
- **規模**: `BGS_MEASURE=1` で全規模（15 ゲーム並行・最終週 50）。**1 回だけ実行した**（標本が少なく、JVM のウォームアップを分けていない）。ウォームアップ前後の分離・複数回の中央値は、人の判断で追加する（未実施）。
- **再現**: `BGS_MEASURE=1 sbt "app/testOnly *PerformanceMeasurementSpec"`。結果は `app/target/performance-sequential.txt`・`performance-concurrent.txt` に書かれる（実行のたびに上書き。この表の値は全規模の実行を転記したもの）。
- **画面**: Playwright の Chromium・Firefox・WebKit で `@ui` 全 27 シナリオ（183 ステップ）が緑。Edge・実機の Safari・スクリーンリーダー・色覚の確認は**未実施**。
- **X-3（ログに秘密を残さない）** の受け入れは、ログの記録（`LogRecord`）と EMF の文字列を検査する。ログの型が資格などを持てない**構造上の保証**であり、検査としては弱い（将来、自由な文字列をログに足したときの退行は検知しにくい）。
