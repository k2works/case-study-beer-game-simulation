# ADR-005: 資格はダイジェストだけを保存し、冪等応答は暗号化して保存する

進行役・復帰・ブラウザセッションの資格は、生の値を保存せず、鍵付き HMAC のダイジェストだけを保存する。

日付: 2026-11-09

## ステータス

提案中（実装済みの決定を事後に記録したもの。レビュー待ち）。コンプライアンスに未達の点がある（後述）。

## コンテキスト

利用者はアカウントを作らず、参加コードと表示名で参加する。進行役は作成時に資格を受け取り、参加者は復帰用の資格でブラウザを閉じた後に同じ役割へ戻る。これらの資格が漏れると、他人の役割や進行役の操作ができてしまう。

- 冪等性のために保存する応答には、復帰用の資格など秘密が含まれうる。
- 個人情報は表示名だけに限る方針。
- 参考: [データモデル設計](../../design/beer-game/data-model.md)

## 決定

- 資格は 32 バイトの乱数（base64url）で発行し、保存するのは鍵付き HMAC-SHA256 のダイジェストだけにする。照合は定数時間で比較する（`timingSafeEqual`）。
- 資格は 3 種類とし、有効期間を分ける。ブラウザセッションは 24 時間、復帰資格は 30 日（復帰のたびに更新）、進行役の資格には有効期限と更新がなく、ゲームが削除されるまで有効（照合はダイジェストの一致のみ）。
- 冪等性のために保存する応答は、AES-256-GCM で暗号化して保存する（鍵は `GAME_CREDENTIAL_ENCRYPTION_KEY`）。
- Cookie は `HttpOnly`、`Secure`、`SameSite=Strict` とする。

### 変更箇所

- `apps/beer-game/src/security/credentials.ts`
- `apps/beer-game/src/application/game-service.ts`（資格の発行・更新・失効）
- `apps/beer-game/src/infrastructure/postgres-game-repository.ts`（`seal`、`open`）

### 代替案

- 生の資格を保存する: DB が漏れた時点で全員の資格が使える。
- ログイン（アカウント）方式にする: 本システムの対象外の概念（パスワード、プロフィール）を持ち込む。
- ダイジェストに鍵を使わない（単純なハッシュ）: 乱数が十分長いため成立はするが、鍵付きにして DB 単体の漏洩への耐性を上げる。

## 影響

### ポジティブ

- DB が漏れても、資格そのものは得られない。
- 資格を失効・更新でき、復帰のたびに回転できる。

### ネガティブ

- 鍵の管理が必要になる。鍵を失うと既存の資格を照合できない。
- 冪等応答の暗号化・復号のコストがある。
- 進行役の資格は、失効や更新の手段がない（漏れた場合は、ゲームの削除まで使われうる）。

## コンプライアンス

- 資格の生の値が、DB、ログ、冪等応答の保存内容に含まれないこと。
- **未達**: `CREDENTIAL_HMAC_KEY` が未設定だと、固定の開発用の値（`local-development-only-key`）にフォールバックする。Terraform の API タスク定義にもこの変数がなく、現状の本番構成では固定の鍵が使われる。本番では必須にして起動時に検証し、Secrets Manager から注入する必要がある（[バックエンドアーキテクチャ](../../design/beer-game/architecture-backend.md) の差分 #6）。
- 資格の単体テストが通ること（`tests/u1/credentials.test.ts`）。
