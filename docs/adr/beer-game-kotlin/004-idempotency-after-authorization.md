# ADR-004: 冪等記録の照合を認可の後に置き、成功した応答だけを保存する

コマンドの処理順を「認証 → 認可の前提検査 → 冪等記録の照合 → 読み込み → `decide` → 追記・投影」とする。`request_digest` に操作者の ID を含め、保存するのは成功した応答だけにする。失効した資格が過去のキーを再送しても、保存済みの応答は返さず 403 とする。

日付: 2026-11-14

## ステータス

提案中（レビュー待ち）

## コンテキスト

変更系の API は `Idempotency-Key` を必須とし、同じキーの再送には、保存した同じ結果を返す（NF-R6、24 時間）。ゲームの作成・参加・復帰の応答は、資格の生の値を含むため、応答を暗号化して保存し、再送でも同じ値を返せるようにしている。

冪等記録の照合を最初に行うと、役割の入れ替えで失効した旧担当者が、以前に成功したキーを再送したときに、保存済みの応答（参加・復帰では資格の生の値）が返りうる。この問題は設計レビューの H4 で指摘された。プロジェクトの `project.md` の Corrections にも、「参加者の入力の判定の順は、占有 → 割当てと token の再検査 → 再送の照合 → 状態の検査にする。認可を再送の照合より先に置く」とあり、beer-game3 で同じ結論に至っている。

失敗の応答を保存するかどうかも、同じ判断の一部である。業務上の失敗は、状態が変われば結果も変わりうる。

## 決定

- コマンドの処理順を、**認証（操作者・資格の有効性）→ 認可の前提検査 → 冪等記録の照合 → 読み込み → `decide` → 追記・投影**とする。冪等記録の照合を、認可より先に置かない。
- `request_digest` は、**本文・対象・操作者の ID** の鍵付き HMAC とする。同じキーでも操作者が違えば、`app.idempotency_key_reused`（409）になる。
- 保存するのは**成功した応答だけ**とする。業務の失敗（`Left`）は保存せず、再送では同じ失敗を再計算して返す。
- 失効した資格が過去のキーを再送しても、認証または認可の前提検査の段階で 403 とし、保存済みの応答を返さない。
- 冪等記録の行は、追記と同じトランザクションで書く。検索は、認可の前提検査の直後に、再試行のたびに行う。

詳細は [バックエンドアーキテクチャ](../../design/beer-game-kotlin/architecture-backend.md) の「冪等性」と設計判断 BD11、[データモデル](../../design/beer-game-kotlin/data-model.md) の「冪等性」を参照。

### 代替案

設計判断 BD11 の案の表による。

- **B: 照合を最初に行い、失敗も保存する（却下）**: 同じ応答を返せて単純だが、失効した旧担当者に、保存済みの応答（資格の生の値）が返りうる。beer-game3 で退けた順序である。
- **失敗も保存する（却下）**: 上の案 B に含まれる。失敗を保存すると、状態が変わった後の再送でも古い失敗が返る。本案では失敗を再計算するため、状態の変化に追随する。失敗の再計算のコストは小さい。
- 操作者の ID を `request_digest` に含めない案は、設計書に案として挙がっていないため、検討対象に加えない。含める理由は、同じキーを別の操作者が使ったときに、別の内容として扱うためである。

## 影響

### ポジティブ

- 失効した資格による再送で、資格の生の値が返らない（NF-S の無効な資格への一律の 403 とも整合する）。
- 失敗を保存しないため、状態の変化に追随する。冪等記録の内容が、成功した応答だけに限られる。
- 追記と同じトランザクションのため、「追記は成功したが記録が無い」状態を作らない。

### ネガティブ

- 再送のたびに、認可の前提検査が先に走るため、照合を先に置く案より、再送の処理がわずかに重い。
- 業務の失敗の再送では、同じ失敗を再計算するため、状態が変わっていれば結果が変わる。これは利用者に見える。
- 認可の前提検査の範囲を実装で誤ると、順序の保証が崩れる。そのため否定テストで守る。

## コンプライアンス

- **B5（進行の継続と資格）**: 「冪等記録の照合を認可の後に置く」を実装する。失効後の再送の否定テスト（役割の入れ替えで失効した旧担当者が、以前に成功したキーを再送すると、保存済みの応答でなく 403）を、AC3.1.*、AC3.2.* の受入と並べて通す（リリース計画 B5）。
- テスト戦略の統合テストとして、次を CI で実行する（[テスト戦略](../../design/beer-game-kotlin/test-strategy.md) の冪等性・競合）。
  - 失効した資格の再送（H4）: 403 で、保存済みの応答を返さない。
  - 冪等記録は成功だけ（H4）: 業務の失敗は保存されず、再送は同じ失敗を再計算して返す。`request_digest` は本文・対象・操作者の ID から作られ、操作者が違えば別の内容として扱う。
  - 制約ごとの再照合（H5）: 同時の重複が、500 にならず保存済みの応答（本文が違えば 409）になる。
  - 資格の再返却: 作成・参加・復帰の再送で同じ資格が返り、生の資格が DB に残らない。
- B6 の並行の統合テストでも、再試行のたびに認可の前提検査と冪等記録の照合が走ることを確認する。
