# ADR-019: 資格の Cookie の名前をタブごとにする（提案）

日付: 2026-11-16

## ステータス

提案。方式（「Cookie の名前をタブごとにする」）は、2026-11-16 にユーザーが選んだ（実装済み）。本書の承認は、人のレビューを待つ。

## コンテキスト

- 資格は Cookie `bg_session`（復帰資格は `bg_recovery`）で運ぶ。Cookie はブラウザの中でタブに関係なく共有されるため、同じブラウザの別のタブで参加すると、進行役の資格が参加者の資格に上書きされる（ロビーが 403 になる）。1 台の端末で進行役と複数のプレイヤーを試す・使うことができない。
- ADR-015 は、資格の値を URL・ログ・本文に含めないと定めている。資格を `sessionStorage` に置く案は、JavaScript が資格を読めるようになり、XSS への防御が弱くなる。

## 決定（提案）

- 画面は、タブ（`sessionStorage`）ごとにランダムな識別子（英数字 32 文字）を作り、すべての要求に `X-Tab-Id` ヘッダーで付ける。識別子は秘密ではない。
- サーバーは、有効な `X-Tab-Id`（`[A-Za-z0-9]{16,64}`）があれば、資格の Cookie の名前を `bg_session_<識別子>`、復帰資格の Cookie の名前を `bg_recovery_<識別子>` にして、発行も読み取りもする。ヘッダーが無い・形が不正なときは、従来の名前のまま。
- 資格の値は、HttpOnly・SameSite=Strict の Cookie のまま。JavaScript は読めない。

## 結果

- 同じブラウザの複数のタブが、別の人として操作できる。従来の呼び出し（ヘッダーなし）は、動作が変わらない。
- Cookie が、タブごとに増える（ブラウザセッションの 24 時間、復帰資格の 30 日で失効する）。
- 「タブを複製」すると `sessionStorage` が複製され、2 つのタブが同じ識別子（同じ人）になる。
- 識別子を知っていても、Cookie の値（資格）が無ければ何もできない。識別子を偽装して他人の Cookie の名前を指しても、自分のブラウザの Cookie しか読めない。

## 却下した案

| 案 | 却下の理由 |
| :--- | :--- |
| 資格を `sessionStorage` に置き、ヘッダーで送る | JavaScript が資格を読める。ADR-015 の「本文に含めない」と XSS への防御を弱める。 |
| ホスト名を変えて Cookie を分ける（`p1.localhost`） | コード変更は要らないが、利用者に手順を強いる。開発の回避策であり、製品の挙動にならない。 |
