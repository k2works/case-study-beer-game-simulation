# ADR-016: 資格の鍵の版を、値の接頭辞で持つ（提案）

資格（ブラウザセッション・復帰資格）のダイジェストは鍵付き HMAC-SHA256 で保存する。鍵を替えても発行済みの資格を使い続けられ、漏れた鍵の版だけを外せるように、資格の値に版を含める。本書は、**AI の提案であって、決定ではない**。実装は B5 Step 4 で済んでおり、人のゲート 4 は 2026-11-15 に承認済み（確認点 1〜6 を報告どおりに確定）。**本書全体のレビュー・承認（`verify`）は未実施のため、ADR としては提案中のまま**。

日付: 2026-11-15

## ステータス

承認済み（2026-11-15、ユーザー。B5 ゲート 8）。

## コンテキスト

- 資格は 256 ビットの乱数で、保存するのは鍵付き HMAC のダイジェストだけ（NF-S4）。B1 は鍵を 1 つだけ持ち、`credentials`・`browser_sessions` の `key_version` 列は常に 1 だった。
- ダイジェストは鍵付きなので、**どの鍵で作ったかを知らないと、提示された値の検証でどの鍵を使うかが決まらない**。鍵を替えると、全資格を使えなくするか、全版を順に試すしかない。
- 漏洩した鍵だけを外す、定期的に鍵を替える、という運用を、利用者に再ログインさせずにできる必要がある（仮説 1。リリース計画）。
- 制約: 設定の名前の変更は Terraform の秘密の形に波及する（B5 は `infra/` を変更しない）。資格の値を URL・ログに出さない。

## 決定（提案）

- **資格の値を `v<版>.<乱数 43 文字>` にする**（`CredentialKeyRing`。application）。発行は現在の版の鍵、検証は**値が示す版**の鍵。形式違い・知らない版（鍵を外した版）は、ダイジェストを作れず「無効」（理由は区別しない。NF-S12）。
- ダイジェストの保存は、版ごとの鍵で作った値と `key_version`（既存の列）。スキーマ変更なし。
- 設定は、現在の版の鍵（`CREDENTIAL_KEY`）、現在の版の番号（`CREDENTIAL_KEY_VERSION`）、旧版の鍵（`CREDENTIAL_KEY_PREVIOUS`）。**名前は提案**で、Terraform の秘密の形への反映は B14 の前に人が確認する。
- 旧版の資格は、旧版の鍵が設定に残る限り、期限まで有効。旧版の鍵を設定から外すと、その版で発行した**すべての**資格が使えなくなる（操作も復帰も 403。現行版の資格は有効）。
- 鍵は `toString` に出さない。

## 影響

### ポジティブ

- ローテーションで、利用者の再接続が要らない。漏れた版だけを外せる。
- 版の判定が値だけで決まるので、全版を試す総当たり（鍵の数に比例する計算）が要らない。
- ミューテーションで、検証が「値が示す版」でなく「現在の版」になると、否定テスト 4 件が落ちることを確認した（Step 4）。

### ネガティブ・リスク

- 資格の値が 46 文字（`v1.` + 43 文字）になり、Cookie の値・復帰コードの長さ・形式の検査に影響する。
- 鍵を外すと、漏れていない資格も使えなくなる（粒度が版単位）。個々の資格の失効は、別（`RevokeCredential`）。
- 鍵の保管・ローテーションの運用手順（Secrets Manager の更新手順、旧版を外す時期）は未整備（B14）。
- 進行役自身の資格は失効・再発行の対象外（ゲート 1 の決定）。進行役の資格が漏れたときに止める手段は、鍵の版を外すことだけ。

## 代替案

| 案 | 内容 | 不採用の理由 |
| :--- | :--- | :--- |
| B: 全版を順に試す | 値に版を含めず、保持する全版の鍵でダイジェストを作り、行を探す | 版が増えるほど、要求ごとの計算とクエリが増える。どの版の資格か分からないため、版ごとの失効の検査（`key_version` との一致）が弱い |
| C: 版を別の項目で送る | Cookie に版を別の値で持つ | Cookie が 2 つになり、片方だけ欠けた状態を扱う。値だけで自己完結する案 A のほうが単純 |
| D: 鍵を 1 つに保つ | 鍵を替えるときは全資格を失効 | 定期ローテーションのたびに全利用者が復帰を要する。漏れた版だけを外す要件（仮説 1）を満たせない |
