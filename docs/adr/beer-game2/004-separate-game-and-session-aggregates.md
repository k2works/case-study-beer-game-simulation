# ADR-004: Game（準備）と Session（進行）の集約を分ける

準備（設定・参加者・役割・観察用の招待）と進行（週・役割の状態・意思決定・結果）を、別の集約にし、開始だけを同一トランザクションで扱う。

日付: 2026-11-09

## ステータス

提案中（レビュー待ち）

## コンテキスト

v1 は、1 つの `Game` 集約に、設定、参加者、セッション、意思決定、結果を全て含め、書き込みのたびに全体を読み込み、`games` の行をロックしていた。準備の操作（低頻度）と、進行中の入力・確定（高頻度）が、同じロックで直列になる。v2 では、同一役割の共同担当と、自動確定が加わり、進行中の更新が増える。

## 決定

- `Game` 集約（`games`、`participants`、`observer_invitations`、`observers`、`browser_sessions`）と、`Session` 集約（`sessions`、`role_decisions`、`week_results`、`week_role_results`）に分ける。
- `Session` は、開始時に、設定の**写し**を持ち、以後 `Game` に依存せず、週を確定できる。
- 進行中の操作（意思決定、確定、停止、再開）は、`sessions` の行だけを版つきでロックする。準備の操作は、`games` の行だけをロックする。
- **開始だけが、2 つの集約をまたぐ**（`Game` を開始済みにし、`Session` を作る）。開始の一回性を保つため、**例外的に同一トランザクション**とする。
- 操作者の役割は、`Game` の割り当てを参照して確認する（読み取りのみ）。開始後は、割り当てを変更しない。

### 代替案

- 1 つの `Game` 集約のまま: 進行中の更新が、準備のロックを共有し、競合が増える。
- 集約を、さらに細かく（役割ごとの状態を別の集約）: 週確定の不変条件（4 役割が揃って一度だけ確定）が、複数の集約にまたがり、分散した整合性が必要になる。

## 影響

### ポジティブ

- 進行中の入力が、準備の操作と干渉しない。
- 集約が、整合性の範囲に合った大きさになる。

### ネガティブ

- 開始が、2 つの集約をまたぐ例外になる。
- 操作者の役割の確認で、`Game` を参照する読み取りが、毎回必要になる（キャッシュまたは `Session` への写しを検討）。

## コンプライアンス

- 進行中の操作が、`games` の行をロックしていないこと（統合テスト）。
- 開始が、二重に実行されないこと（冪等性のテスト）。
