# ADR-002: v1 の ADR の引き継ぎ方を定める

beer-game（v1）の ADR 001〜008 について、v2 で、引き継ぐ・変更する・置き換えるものを明示する。

日付: 2026-11-09

## ステータス

提案中（レビュー待ち）

## コンテキスト

v1 には、設計判断を記録した ADR が 8 件ある。v2 は要件と設計を改訂して作り直すため、どの判断が有効で、どれが変わるかを、明示しないと、二つの系列の ADR が混在して、読み手を迷わせる。

## 決定

v1 の ADR を、次のとおり扱う。v1 の ADR のファイルは、履歴として残し、内容は変更しない。

| v1 の ADR | v2 での扱い | v2 の ADR |
| :--- | :--- | :--- |
| 001 週次計算を純粋関数として分離する | **引き継ぐ** | （変更なし。役割別の週結果を返す点は ADR-005） |
| 002 状態を持たない API とゲーム単位の行ロック | **引き継ぐ**（集約ごとの行ロックと版へ発展） | ADR-004 |
| 003 イベントソーシングを採用せず、アウトボックスと投影の簡易形 | **変更**（投影の再構築をやめ、週結果を役割別の行で保存） | ADR-005 |
| 004 SSE で版を通知し、状態は再取得 | **一部変更**（再生を省く） | ADR-006 |
| 005 資格はダイジェストだけを保存 | **引き継ぎ、拡張**（鍵の版、有効期限と失効） | ADR-009 |
| 006 SPA でルーターと状態管理ライブラリを導入しない | **一部変更**（ルーターを導入） | ADR-010 |
| 007 CloudFront の単一オリジン | **引き継ぎ、拡張**（独自ドメイン、TLS、ヘッダー） | ADR-011 |
| 008 保持削除を SQS と所有者別ワーカーの Saga で実行 | **置き換える**（1 トランザクションのカスケード削除） | ADR-007 |

### 代替案

- v1 の ADR を、v2 のディレクトリへ複製して改訂する: 番号と履歴が混ざり、v1 の記録が失われる。
- v1 の ADR をすべて有効とする: 構造の変更（集約の分離、キューの廃止など）と矛盾する。

## 影響

### ポジティブ

- どの判断が引き継がれ、どれが変わったかが、1 か所で分かる。
- v1 の記録を、履歴として保てる。

### ネガティブ

- 二つの系列の ADR を、読み手が参照する必要がある。

## コンプライアンス

- v2 の ADR が、置き換えた v1 の ADR を、備考で参照していること。
- v1 の ADR を、変更しないこと（履歴）。
