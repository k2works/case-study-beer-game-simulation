# ADR-010: URL ルーターを導入し、機能単位の構成にする

フロントエンドに URL ルーターを導入し、ゲームを URL で表す。資格は Cookie のままとする。構成は機能単位（`features/`）にする。

日付: 2026-11-09

## ステータス

提案中（レビュー待ち）

## コンテキスト

v1 は、URL ルーターを使わず、`useState` で画面を切り替えていた。このため、再読み込みでゲーム ID とセッション ID を失い、特に**進行役が、ブラウザを閉じると、コンソールへ戻れなかった**。また、`CreateJoinLobby.tsx`（約 415 行）に、作成・参加・ロビーが同居していた。

## 決定

- URL ルーターを導入する（候補: react-router。導入時に承認を得る）。URL には、**ゲーム ID だけ**を含め、資格や参加コードを含めない。
- 画面を開いたとき、Cookie の資格で権限を確認し、権限が無ければ、参加・復帰の画面へ誘導する。
- 画面の切り替えごとに、`document.title` を更新し、見出しへフォーカスを移す。
- `src` を、`features/`（game-setup、participation、observer、play、console、review、retention）と `shared/` に分ける。
- 状態管理ライブラリは、引き続き導入しない（画面ごとのカスタムフック）。

### 代替案

- ルーターなし（v1）: 再読み込みで戻れない問題が残る。
- 自前の最小のルーター: 標準的な機能（ネスト、ガード、フォーカス）を再実装する手間がある。
- 状態管理ライブラリの導入: 共有する状態が少なく、過剰。

## 影響

### ポジティブ

- 再読み込みやブラウザの再起動で、進行役も参加者も戻れる。
- 画面ごとの題名とフォーカスで、アクセシビリティが上がる。
- 機能ごとに、変更の影響が閉じる。

### ネガティブ

- 依存関係が 1 つ増える。
- URL の設計と、権限のない場合の誘導の実装が必要になる。

## コンプライアンス

- 進行役が、再読み込みしても、コンソールへ戻れること（E2E、AC3.2.4）。
- URL に、資格や参加コードが含まれないこと。
