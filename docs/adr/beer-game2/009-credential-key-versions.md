# ADR-009: 資格の鍵に版を持たせ、すべての資格に有効期限と失効を持たせる

進行役の資格、復帰資格、観察用の招待、ブラウザセッションのすべてに、有効期限と失効を持たせ、鍵は複数の版を同時に保持し、本番では必須とする。

日付: 2026-11-09

## ステータス

提案中（レビュー待ち）

## コンテキスト

v1 では、資格のダイジェスト用の鍵が、未設定だと固定の開発用の値になり、本番の構成でも設定されていなかった。進行役の資格には、有効期限も失効の手段も無く、漏れた場合に被害を止められなかった。鍵に版が無く、ローテーションすると、既存の資格がすべて無効になる。

## 決定

- 資格は、256 ビットの乱数で、保存は鍵付き HMAC のダイジェストと**鍵の版**だけ。
- 鍵は、**複数の版を同時に保持**する（Secrets Manager の複数の値）。新しい資格は最新の版で、検証は、保存された版の鍵で行う。ローテーション後も、旧版で発行した資格を、期限まで検証できる。
- **本番では、鍵の設定を必須**とし、未設定なら、起動に失敗する。
- 進行役の資格、復帰資格、観察用の招待、ブラウザセッションに、有効期限と失効を持たせる。進行役は、資格を失効・再発行できる。
- 有効期間の既定値は、設計で決める（ブラウザセッション 24 時間、復帰資格 30 日、進行役の資格はゲームの保持期間内など。運営者と合意する）。

### 代替案

- 鍵を単一のまま: ローテーションで全資格が無効になる。
- 資格を平文で保存: DB の漏洩で、全資格が使われる。
- 失効を設けない: 漏洩時に被害を止められない。

## 影響

### ポジティブ

- 漏洩時に、被害を止められる。
- 鍵を、無停止でローテーションできる。
- 本番の誤設定を、起動時に検出できる。

### ネガティブ

- 鍵の管理（複数の版、ローテーションの手順）の運用が必要になる。
- 有効期間の既定値を、運営者と合意する必要がある。

## コンプライアンス

- 本番の起動で、鍵が未設定なら失敗すること（テスト）。
- 失効した資格・期限切れの資格が、拒否されること。
- ローテーション後も、旧版の資格が、期限まで有効であること。
