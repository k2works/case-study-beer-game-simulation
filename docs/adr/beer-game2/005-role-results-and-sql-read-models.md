# ADR-005: 週結果を役割別の行で保存し、観察・振り返り・出力は SQL で返す

確定の瞬間に、役割別の週結果を行として保存し、観察、振り返り、出力は、その表への SQL で返す。投影のイベントからの再構築は行わない。

日付: 2026-11-09

## ステータス

提案中（レビュー待ち）

## コンテキスト

v1 の週確定のイベントは、全役割の**合計だけ**を持ち、振り返りと出力が役割別の推移を返せなかった（ブルウィップ効果の説明に必要）。観察と振り返りは、リクエストのたびに、ゲームの全イベントから投影を再構築していた。投影テーブルは、定義だけで使われていなかった。

## 決定

- 週確定の同じトランザクションで、`week_results` と、**役割別の行 `week_role_results`**（需要、出荷、発注、週末在庫、週末受注残、週次費用、累積費用）を保存する。
- 観察（確定済みの週の合計と、公開範囲・寄与者数による抑止）、振り返り（役割別の時系列）、出力（CSV・JSON）は、この表への SQL で返す。
- イベントからの投影の再構築と、投影テーブルは作らない。
- 週確定のイベントにも、役割別の週結果を含める（監査と将来の配信のため）。

### 代替案

- 完全なイベントソーシング: 実装と学習のコストが高く、本システムの規模に見合わない。
- v1 のまま（イベントから再構築）: 役割別の値が無く、長いゲームで読み込みが増える。
- 投影テーブルを作り、イベントで更新: 更新と再構築の仕組みが要り、整合性の確認が増える。

## 影響

### ポジティブ

- 役割別の振り返りと出力が、単純な問い合わせで実現できる。
- 観察と振り返りの応答時間が、ゲームの長さに依存しない。
- 投影の再構築と、その失敗モードが無くなる。

### ネガティブ

- 確定のトランザクションで、書き込む行が増える（1 週で 1 + 4 行）。
- 公開範囲の抑止を、SQL とアプリで正しく実装する必要がある（テストで守る）。

## コンプライアンス

- 振り返りと出力が、役割別の値を返すこと（受入条件 AC4.2.1、AC4.3.1）。
- 観察が、役割別の値と将来の需要を返さないこと（AC4.1.2、AC4.1.3）。
