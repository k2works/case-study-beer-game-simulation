# ADR-006: SSE は版の通知だけとし、取りこぼしの再生をしない

SSE は、集約の種別と版の通知だけを送り、再接続時の取りこぼしの再送は行わない。クライアントは、接続のたびにスナップショットを取得して追いつく。

日付: 2026-11-09

## ステータス

提案中（レビュー待ち）

## コンテキスト

v1 の SSE は、版の通知に加えて、`Last-Event-ID` によるイベントの再生と、カーソルの照合を実装していた。しかし、クライアントは、通知を受けるたびに、スナップショットを再取得しており、再生した内容は使われていなかった。再生の実装（`eventsSince`、カーソルの確認）は、複雑さだけを増やしていた。

## 決定

- SSE は、`state-version`（集約の種別と版）だけを送る。内容は運ばない。
- 再生と、`Last-Event-ID` の処理は実装しない。
- クライアントは、接続の開始と再接続のたびに、スナップショットを取得し、通知のたびに再取得する。版が古い応答は適用しない。
- 切断時は、1 秒間隔のポーリングに切り替える。
- サーバーは、`LISTEN/NOTIFY` を合図に通知し、定期の照合（数秒）で、`NOTIFY` の欠落を補う。

### 代替案

- v1 のまま（再生あり）: 使われない機能の保守が続く。
- WebSocket: 双方向は不要で、プロキシ越しの扱いが複雑になる。
- ポーリングのみ: 2 秒以内の反映に短い間隔が要り、負荷が増える。

## 影響

### ポジティブ

- サーバーの実装が単純になる。
- 通知に情報が載らないため、役割別の開示制御を通知経路に実装しなくてよい。

### ネガティブ

- 再接続のたびに、スナップショットを取得する負荷がある（軽量な取得に限る）。

## コンプライアンス

- SSE の応答が、状態の内容を含まないこと。
- SSE を遮断しても、ポーリングで最新の状態へ収束すること（E2E）。
