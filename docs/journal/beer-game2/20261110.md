# 開発ジャーナル 2026-11-10

## やったこと

リリース計画と Bolt 1 計画の確認から始め、承認（全 5 項目）を受けて、Bolt 1 の Step 1〜10 を TDD で実装した。結果は [Bolt 1 終了報告](../../development/beer-game2/bolt_1_report.md) を参照。

## 判断

- **集約は不変にし、操作は新しい集約とイベントを返す**。ルールを集約に集め、ユースケースは読み込み・呼び出し・保存だけにした。メモリ上の `UnitOfWork`（コピーして、成功したら差し替える）で、原子性を DB なしでも検証できた。
- **`simulateWeek` は Session から独立した純粋関数**にした。役割別の週結果（発注を含む）は Session 側で付ける。
- **解除（unassign）を計画外で追加**した。AC1.2.5 を「拒否」にすると、付け替えの手段が要るため。
- **冪等記録の応答は AES-256-GCM で暗号化**した（計画どおり）。鍵は設定から渡し、本番で無ければ起動に失敗する。

## 詰まった点

- 「ゲートを通さず進める」ことになった。目標（U1 の完了）に従って連続で進めたが、計画の「密」と矛盾する。報告に明記し、人の検証を依頼する形にした。
- 受入条件の定義を、実装の**後**に読み返して食い違いに気づいた。最も大きな手戻りだった。
- DB を止める試験で、再接続のない `LISTEN` 接続がプロセスごと落ちた。

## 次回に活かすこと

- 受入条件の原文を、テストを書く前に読む。
- 「握りつぶし」を許さない（`.catch(() => {})`、静かに外れる置換）。
- 人の検証時間を、所要の見積もりに含める。
