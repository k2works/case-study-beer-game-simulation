# ロールバック手順書

> **状態: 定義のみ（AWS 未実行）。**

## 通常（アプリだけの変更）

1. 本番は BLUE_GREEN: 切り替え後の待ち時間（10 分）は旧版が残る。その間に重大のアラーム（5xx・正常なタスク 0）が鳴れば、自動で旧版へ戻る。
2. 手動で戻すときは、直前の版（ダイジェスト）を `image` に指定して、サービスを更新する（`aws ecs update-service --task-definition <直前の版>`）。
3. 戻した後、`/api/v1/ready` が 200、ゲームの状態の取得が成功することを確認する。

## マイグレーションを伴う場合（2 段階リリース）

- スキーマ・イベントの形の変更は、**読む版 → 書く版**の 2 段階で出す（B12）。先に「新しい形も読める」版を出し、全台がそろってから「新しい形で書く」版を出す。現在のコードは、**現在より新しいスキーマ版のイベントを読まずに止める**（古い版が新しい形を誤って解釈しない）。
- したがって、書く版を出した後は、読む版より前へは戻せない（新しい形のイベントが残る）。戻すときは、まず「新しい形も読める」版へ戻し、書く版の修正を出し直す。
- マイグレーションの SQL は、前方互換（列の追加など）を原則とし、削除・型の変更は、2 つのリリースに分ける。

## 戻せないケース

- 削除済みのゲーム（保持期限後の削除）は戻せない。バックアップに残る期間は 7 日（自動バックアップ。復元は [復元の手順書](./restore.md)）。復元すると削除済みのゲームが再び現れるので、復元後は retention を 1 回実行する。
- 復元の時点より後の操作は失われる。
