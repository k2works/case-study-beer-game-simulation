    リリースの準備状況（Kotlin 版 U1〜U6）¶

    この文書は、人が次に何を判断・確認すれば、Kotlin 版をリリースへ進められるかを、1 か所にまとめた総覧です。承認の記録ではありません。 数値・状態は、各 Bolt の終了報告と Unit の総括（U1・U5・U6）を出典とし、B15 の時点（2026-11-18）の状態です。詳細は各報告を参照してください。

    2. 人の判断が要る項目（統合）¶

    出典の番号は各報告のものです。重複は整理しました。

    A. 受け入れを左右するもの¶

    # 項目 出典
    A1 承認ゲートの扱い: B1〜B4・B7〜B15 のゲート、ステップ計画、コードの全行理解、デモ項目の人の実操作を、人が検証するか。以降のゲートの密度を決める実績が無い（B1 の仮説 5 は判断不能） U1 総括、各報告
    A2 SSE を実装するか（NF-P2・P4・P7・R10・C3 の前提。画面の自動更新。B1 の持ち越し） B1、B13、B15
    A3 NF-P1 の読み方（75 並行を隙間なくと読むか）と、接続プール・保存の経路の改善 B15
    A4 投影の再構築が目標の約 4 倍遅い（NF-P18。1 ゲーム 1052 件で p95 4.1 秒）。改善するか、目標を変えるか B15
    A5 マイグレーションの承認: 001〜005・V102（承認済み）以外の V006（保持）・V103（権限）ほか。V101 と V102 の順序（永続環境の前に番号を付け替える方針） B1、B2、B11

    B. 設計・仕様の判断¶

    # 項目 出典
    B1 ブルー/グリーンを ECS の組み込み方式にするか、設計書どおり CodeDeploy か（本番で初めて動く） B14
    B2 RPO 0 の範囲（PITR では 0 にならない）、RTO 15 分（PITR で収まる保証がない）に別の値を置くか B14
    B3 CloudFront → ALB を HTTPS にするか。KMS・プライベートサブネット・DB ログインロールの分離（B3 の設計との差 4 点） B3、B14
    B4 保持の起点（作成時が暫定。終了時起点の案）。バックアップ 7 日と手動のスナップショットの扱い B11、B14
    B5 書く版の切り替え（WRITE_SCHEMA_VERSION の提案。未実装）。再構築中のコマンドの応答（待つか 503 か） B12、B14
    B6 ASM-01（キット準拠の既定の需要系列）の確定。JSD 準拠の受入判定は保留のまま B1
    B7 資格の期限・参加の上限の、運営者との合意（R11）。ADR-020（計画外のタブごとの資格 Cookie）の承認 B5、B6
    B8 ヘルプの「1 週に起きること」を、教材の 12 ステップの本文にするか（現在は業務ルール BR-02〜BR-09 の言葉） B15
    B9 層単位の PMD の緩和の承認と ADR、仕様の後追い修正 7 件、追加した依存の範囲、ADR の要否（多数が提案中） B2、B3
    B10 SIGTERM の終了コード（143 と設計の 0）。業務のスモークテスト。手動の再試行（POST …/retry）と通知の経路 B3、B11

    C. 運用・インフラ・CI¶

    # 項目 出典
    C1 GitHub の設定: Environment・変数（BEER_GAME_KOTLIN_AUTO_DEPLOY・RETENTION_TASK_FAMILY・VERIFY_TASK_FAMILY・RDS_INSTANCE）・production の保護ルール・シークレット。すべて未設定 B3、B14
    C2 運用の決定: オンコール・連絡窓口・通知先のメール、研修中だけ通知する運用（training_alarms_enabled）の自動化 B13、B14
    C3 閾値の見直し（競合率・再試行・GC・プール、ブルー/グリーンの待ち時間 10 分）。B15 の実測: プールは隙間なく同時の負荷で 10/10、待ちが最大 53 B13、B14、B15
    C4 CI の依存関係・秘密情報の検査（Gradle・gitleaks など。新しい外部ツール）。開発用 npm 依存の脆弱性 14 件（high 7） B15
    C5 静的検査の追加（tflint・checkov・actionlint・shellcheck・Trivy）、actions の SHA 固定、イメージの強化 B3
    C6 生きたドキュメントの公開、Cucumber のタグの整合検査ほか（B2 の申し送り） B2

    D. 品質の人の確認¶

    # 項目 出典

    3. AWS 適用の前提（別ゲート。R10）¶

    AWS への適用は、いずれの Bolt でもしていない・接続していない。適用の前に、人が決めるもの（本番の運用手順書「適用の前に、人が確認する項目」、Bolt 3 終了報告）。
