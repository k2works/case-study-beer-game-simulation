    実施中に見つけた不具合・事実¶

    1. タスク定義が Kotlin 版の写しで、Rust のアプリが動かない定義だった（重大。是正済み）: infra/modules/ecs は、APP_ENV・DB_KIND・JDBC の DB_URL・MIGRATE_ON_START などを渡し、Rust のアプリが読む DATABASE_URL・ENVIRONMENT を渡していなかった。そのままデプロイすると、コンテナは「DATABASE_URL が必要です」で起動できず、起動できてもメトリクスの Environment が local のままで、アラーム・ダッシュボードが永久に欠測になる。B14 で定義した心拍のアラームが前提とする経路も、同じ原因で成り立たなかった。直し方: アプリが DB_HOST・DB_USER・DB_PASSWORD（と DB_PORT・DB_NAME・DB_SSLMODE）から接続 URL を組み立てる（DATABASE_URL があれば優先。ローカルの動作は変えない。ECS は Secrets Manager の値を 1 つの URL に合成できないため）。Terraform は、アプリが読む変数だけを渡す。AWS 上の起動は未確認。
    2. アプリにセキュリティヘッダーが無かった: 共有 feature の受入が、実装の前に失敗して検出した。
    3. retention が最小権限の削除ロールに切り替えない（未実装）: Terraform の DB_DELETER_ROLE は Kotlin 版の変数で、Rust のアプリは読まない（削除用のロール beergame_deleter は、テストだけが使う）。実際の retention は、接続のログインユーザーで動く。DB のログインロールの分離は、計画どおり定義していない（人の判断）。
    4. ステージングの ENVIRONMENT も同じ原因で欠けていた（1 に含む）。
    5. 共有の画面（web/）は Kotlin 版のもの: デプロイの静的ファイルの公開は、apps/beer-game-kotlin/web を使う。

    6. テストが、偶然通っていた: 復元スクリプトの「引数が足りなければ失敗」の 2 件は、スクリプトが無い間も（bash が失敗するので）通っていた。スクリプトを作った後は、本物の振る舞い（引数の検査）で通る。

    7. CI の infra ジョブが、最初の push で 1 度失敗した（terraform fmt -check。私が挿入したコメントが、整形の揃えを崩した）。ローカルの確認に terraform fmt -check を入れていなかったためで、validate だけを確認していた。直して再度 push し、check・infra・container はすべて成功した（最終のコミット 19339ea）。同じ原因の terraform fmt の指摘は、CI が検出する。あわせて、ecs/main.tf に残っていた Kotlin 版の古いコメント（Main.kt・SET ROLE）を改めた。

    未確認・簡略化（人の判断が要る項目）¶

    1. AWS 上の動作は、すべて未確認: ワークフローの実行、OIDC の引き受け、ブルー/グリーンの切り替えと自動の戻し、定期タスクの起動、復元（--execute）、アプリのコンテナの起動、EMF の取り出し、アラームの評価。適用前の確認（本番の運用手順書）の 10 項目は、すべて未実施。
