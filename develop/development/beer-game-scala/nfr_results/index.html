    NFR 検証表の結果（B15）¶

    非機能要件（non-functional.md）の NF-C（9）・NF-O（13）・NF-P（20）・NF-R（17）・NF-S（25）の、計 84 件の、B15 時点の結果です。数値は実測だけを書き、測っていないものは「未測定」「未実施」と書いています。設計書は変更していません。人の承認は得ていません。

    結果の語¶

    語 意味
    達成 自動の試験・実測で、要件を満たすことを確かめた
    一部 要件の一部だけ確かめた、または一部が未実装・未確認
    未達 実測・確認で、要件を満たさなかった（または、要件の機能が未実装）
    定義のみ 定義（Terraform・ワークフロー・手順書・閾値の表）はあるが、AWS 上では動かしていない
    未測定 B15 までに測っていない
    未実施 環境（AWS・複数タスク・人の操作）が無く、実施していない
    適用外 現在の設計では適用しない

    件数¶

    判定 件数
    達成 23
    一部 35
    未達 4
    定義のみ 8
    未測定 8
    未実施 2
    適用外 4
    合計 84

    計測の条件と限界¶

    • 環境: 手元（macOS の Docker Desktop）の実 PostgreSQL 18.6（Testcontainers、接続プールは既定）。インプロセスの HTTP ルーターを呼ぶ（ネットワーク・ブラウザ・SSE・複数タスクを含まない）。AWS（Fargate・RDS）の値ではない。
    • 規模: BGS_MEASURE=1 で全規模（15 ゲーム並行・最終週 50）。1 回だけ実行した（標本が少なく、JVM のウォームアップを分けていない）。ウォームアップ前後の分離・複数回の中央値は、人の判断で追加する（未実施）。
    • 再現: BGS_MEASURE=1 sbt "app/testOnly *PerformanceMeasurementSpec"。結果は app/target/performance-sequential.txt・performance-concurrent.txt に書かれる（実行のたびに上書き。この表の値は全規模の実行を転記したもの）。
    • 画面: Playwright の Chromium・Firefox・WebKit で @ui 全 27 シナリオ（183 ステップ）が緑。Edge・実機の Safari・スクリーンリーダー・色覚の確認は未実施。
    • X-3（ログに秘密を残さない） の受け入れは、ログの記録（LogRecord）と EMF の文字列を検査する。ログの型が資格などを持てない構造上の保証であり、検査としては弱い（将来、自由な文字列をログに足したときの退行は検知しにくい）。

    実測値（手元・1 回）¶

    指標 値
    15 ゲーム並行・最終週 50（全体の所要） 125 秒（5xx 0 件・4xx 0 件）
    saveDecision n=3000、p50 328 ms、p95 856 ms、max 1859 ms
    commitWeek n=750、p50 300 ms、p95 798 ms
    確定から反映（commit + 状態取得）（NF-P2） 並行: p95 1388 ms（上限 4 秒）。1 ゲームの逐次: p95 499 ms
    出力（CSV・JSON、最終週 50）（NF-P9） 並行: p95 344 / 301 ms。逐次: 138 / 130 ms
    復盤（review） 並行: p95 304 ms。逐次: 157 ms
    createGame（並行 15 件） p50 1368 ms、max 1804 ms（初回の接続・JIT を含む）
    起動時間（コンテナ → /ready 200） 約 18〜23 秒（B14 の実測、Docker Desktop。Fargate の値は未測定）

    NF-C（互換・制約）¶

    ID 要件 判定 根拠・限界
    NF-C1 15 ゲーム・各 5 人（75 の同時接続）の初期の容量 一部 15 ゲーム並行・最終週 50 を、エラー 0 件で完了（実測・インプロセス）。SSE の接続は未実装。ネットワーク・ブラウザは含まない
    NF-C2 全 60 役割が 10 秒以内に確定の入力。エラー率 1% 未満、重複した副作用 0 一部 並行の負荷でエラー 0 件・重複 0（ゲームごとの結果は 1 回分）。「10 秒以内に一斉」の形は再現していない（最終週まで連続）
    NF-C3 25 ゲーム・100 接続を 2 つ以上のインスタンスで処理 未実施 複数インスタンスは未実施。SSE も未実装
    NF-C4 ステートレスな API で水平に拡張。スティッキーセッション不要 一部 状態・レート制限・冪等記録を DB に置く設計。複数インスタンスでの確認は未実施。api の中の定期の掃引は本番で止める（B14）
    NF-C5 キャパシティのアラート 定義のみ Terraform の定義。DB プールの使用率の指標は未出力
    NF-C6 保存容量の見積もり（30% の余裕） 未測定 容量モデルは未作成
    NF-C7 非同期投影・スナップショットへの移行の条件を定める 一部 設計書に記述。移行の実施は不要（再生が 1〜3 ms）
    NF-C8 イベント量は千件前後、最悪 2000 件。1 ゲーム数 MB 以下 一部 最終週 50 で 652 件。保存回数の上限（9 回）で最悪値を抑える。保存量（バイト）は未測定
    NF-C9 スナップショットは、再生が NF-P15・P3 を圧迫すると分かった場合だけ導入 達成 現状の再生は 1〜3 ms（メモリ上）で圧迫しないため、導入していない（NF-P15 の読み込み込みの値は未確認）

    NF-O（運用・観測）¶

    ID 要件 判定 根拠・限界
    NF-O1 構造化ログに相関 ID・操作・結果・版・所要時間。秘密を含めない 一部 相関 ID・操作・結果・所要時間・秘密を含まない（X-3 の受け入れ）。「版」は含めていない
    NF-O2 相関 ID を HTTP・トランザクション・イベントの封筒・SSE に伝える 一部 HTTP の応答とログには伝える。イベントの封筒・トランザクションへは未対応
    NF-O3 応答時間・エラー率・競合と再試行の回数・ロールバック・投影の更新時間・ロックの待ち・SSE・接続数・プールの使用率を計測 一部 応答時間・要求数・5xx の率（EMF）、定期タスクの結果。競合・再試行・ロールバック・接続プール・SSE の指標は未出力
    NF-O4 アラート（API p95・反映 p95・競合・ヒープなど） 定義のみ Alarms と Terraform の一致をテストで検査（AlarmTerraformSpec）。指標が出ていないアラームがある・未適用
