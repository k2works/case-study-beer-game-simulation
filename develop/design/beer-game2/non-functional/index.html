    非機能要件定義 - ビールゲームシミュレーション（v2）¶

    概要¶

    本書は、beer-game2（v2）の非機能要件を、測定できる形で定義します。docs/ を正本とします。

    beer-game（v1）の 非機能要件（61 件、実装の状況と 12 件の差分）を出発点に、v2 の設計と範囲を反映して改訂しました。表の「v1 の状態」は、v1 の実装の状況です。△・✗・未測定は、v2 で満たす対象です。

    • 要件定義（v2）の NFR-01〜NFR-12、aidlc/ の Unit ごとの NFR 要件（U1〜U5）、v1 の実測を統合しています。
    • 数値目標は、運営者（ビジネス側）と合意する前提の提案です。出典の ID（例: U1 NFR1.1）は aidlc/spaces/default/intents/261027-beer-game-development/construction/ 配下の各 Unit の記録を指します。

    凡例（v1 の状態）¶

    記号 意味
    ✓ v1 で、実装または設定があり、コードで確認した（v2 でも引き継ぐ）
    △ 一部のみ（不足を備考に記載）
    ✗ 未実装
    未測定 目標はあるが、満たしているか測っていない

    品質特性の優先順位¶

    非機能要件定義ガイド の ISO/IEC 25010 の分類で、学習教材としての性格から優先順位を付けます。

    優先 品質特性 理由
    1 機能の正確性・信頼性（整合性） 週次計算の忠実性と、確定の一回性が、教材の価値そのもの
    2 セキュリティ（機密性・完全性） 役割ごとの情報制約が、学習条件の前提。資格の漏洩は他人の役割の操作につながる
    3 性能効率性・使用性 研修中の操作が滞らないこと。アクセシビリティは要件
    4 保守性・観測性 研修中の障害に気づき、直せること
    5 可用性（SLO） 研修の時間帯に使えること。常時の高可用性までは求めない
    6 拡張性・移植性 想定規模（15 チーム）を満たし、増やせる余地を残す

    SLO の要約（提案）¶

    項目 目標 出典
    月間可用性 99.5%（事前に通知した計画停止は除外） U1 NFR2.1
    研修中の完全停止の検知 1 分以内に通知 U1 NFR2.2
    確定済み週のデータ損失（RPO） 0 U1 NFR2.3
    障害からの復旧（RTO） 15 分 U1 NFR2.4
    入力確定（サーバー側）の p95 1 秒以内 NFR-03、U1 NFR1.1
    週確定から全画面への反映の p95 2 秒以内 NFR-03、U1 NFR1.2
    保持期限後の削除 期限到達の 99% を 24 時間以内に完了 U4 NFR1.2

    学習ビューの可用性は U3 が 99.9% としていますが、システム全体の SLO（99.5%）を超える目標は意味を持たないため、全体の 99.5% に統一します。

    性能要件¶

    ID 要件 測定方法 出典 v1 の状態
    NF-P1 15 チーム（各 4 参加者 + 進行役）の同時利用で、意思決定の送信と役割別の状態取得の p95 を 1 秒以下とする 75 並行、15 分の定常負荷。検証エラーと認可エラーは別の系列にする NFR-03、U1 NFR1.1 △
    NF-P2 週確定から、接続中の全ブラウザが最新の状態を表示するまでの p95 を 2 秒以下（p99 5 秒以下）とする サーバーの確定時刻と、ブラウザの描画時刻を、同じ相関 ID で計測する NFR-03、U1 NFR1.2、U3 NFR1.2、U5 NFR1.11 未測定
    NF-P3 週確定のサーバー処理は、p95 1 秒以下、p99 2 秒以下（4 役割、50 週相当）とする 最大の状態での計測 U1 NFR1.3 未測定
    NF-P4 SSE が使えない場合、1 秒間隔のポーリングに移り、確定から 4 秒以内に最新の版を表示する SSE を遮断した E2E U1 NFR1.4、U5 NFR1.12 △
    NF-P5 ブラウザでの入力確定から成功の表示までの p95 を 1 秒以下とする（描画を含む） ブラウザ E2E で 75 ユーザーの負荷 U5 NFR1.10 未測定
    NF-P6 停止・再開・代理入力の API は、p95 500 ms 以下、p99 1 秒以下とする API の計測 U2 NFR10.1 未測定
    NF-P7 再接続時の状態取得は、75 並行で p95 1 秒以下。SSE の再接続後 5 秒以内に最新の版を表示する 負荷試験 U2 NFR10.2、10.3 △
    NF-P8 観察と振り返りの取得は、15 ゲーム・90 読み手で、p95 1 秒以下、p99 2 秒以下とする。v2 は、役割別の週結果の表への SQL で返す（イベントからの再構築をしない） 30 分の負荷試験 U3 NFR1.1 未測定（v1 は、リクエストごとにイベント全件から再構築）
    NF-P9 エクスポートは、受理 1 秒以内、50 週 × 4 役割の CSV と JSON を 30 秒以内（p95）に完了する エンドツーエンドの計測 U3 NFR1.3 未測定
    NF-P10 保持状態の取得は、p95 1 秒以下とする HTTP の計測 U4 NFR1.1 未測定
    NF-P11 期限に達した削除の Saga の 99% を、24 時間以内に完了する completedAt - deleteAfter U4 NFR1.2 △（定期起動は 5 分（コーディネーター）、1 分（所有者）間隔で、設計は満たせる）
    NF-P12 1 リクエストの処理量に上限を設ける（数量 0〜1000、リクエスト 64 KB、履歴は必要な範囲だけ） 境界値のテスト U1 NFR3.9 ✓
    NF-P13 共同入力の保存（競合の検出を含む）は、p95 1 秒以下とする。競合時は、最新値と保存者を、同じ応答で返す API の計測、並行のテスト FR-16、NFR-03 新
    NF-P14 自動確定は、最後の意思決定の保存から確定の完了まで、p95 1 秒以下とする（保存と同じトランザクション） API の計測 FR-18、NFR-03 新

    実測（2026-11-09、npm run load:u5）: 15 ゲーム、75 の SSE 接続、375 件の取得で、失敗は 0 件、取得の p95 は約 94 ms、SSE 接続の p95 は約 150 ms でした。ただし、1 プロセス・メモリ上のサービスでの診断で、データベース経由、複数タスク、ブラウザの描画は測っていません（NF-P1 を △ とした理由）。

    備考（NF-P8）: データベース利用時は、観察と振り返りの取得のたびに、ゲームの全イベントから投影を作り直します（ADR-003）。長いゲームでは目標を超える可能性があります。

    信頼性・可用性要件¶

    ID 要件 測定方法 出典 v1 の状態
    NF-R1 月間可用性を 99.5% とする 合成監視による SLI U1 NFR2.1 ✗（SLI が無い）
    NF-R2 研修の時間帯に、完全な停止または確定の失敗を、1 分以内に通知する アラートの訓練 U1 NFR2.2 ✗
    NF-R3 確定済みの週の RPO は 0。永続化のコミット後にだけ成功を返す プロセスの強制停止と再起動の試験 U1 NFR2.3、U2 NFR13.1 △（設計は満たす。強制停止の試験は無い）
    NF-R4 障害（アプリ・DB）の RTO は 15 分。最後の確定済みの週から再開できる 復元の訓練 U1 NFR2.4、U2 NFR13.2 未測定（訓練なし）
    NF-R5 週の確定、冪等記録、週結果、イベントは、同じトランザクションで全部成功か全部失敗とする 障害の注入 NFR-02、U1 NFR2.5 △（実装は満たす。注入のテストは無い）
    NF-R6 同じ冪等キーと同じ内容の再送は同じ結果を返し、内容が違えば競合とする。保持は 24 時間とする（v2 で設計に統一） 統合テスト U1 NFR2.6 ✓（v1 の実装は 30 日）
    NF-R7 楽観的排他の競合は、受理済みの書き込みを失わず、最新の安全な状態と版を返す 並行更新のテスト U1 NFR2.7 ✓
    NF-R8 データベースは、時点復旧が可能なバックアップを持ち、リリース前と方針の変更時に復元の訓練を行う 訓練の記録 U1 NFR2 △（Multi-AZ、7 日の自動バックアップは設定済み。訓練なし）
    NF-R9 データベースが使えない場合、受理済みと表示せず、再試行できる失敗と相関 ID を返す 障害の注入 U1 NFR2 △（相関 ID 付きの 500 は返す。再試行できる失敗の区別は無い）
    NF-R10 SSE とポーリングの障害は、状態の変更を妨げず、再接続後に権威ある版へ収束する E2E U1 NFR2、NFR-05 ✓
    NF-R11 保持削除は、誤って完了とせず、同じ削除 ID で最大 5 回、指数バックオフと揺らぎで再試行する 障害の注入 U4 NFR2.2〜2.4 ✓
    NF-R12 再起動後に、進行中の Saga、所有者ごとの進捗、再試行の予定を復元する 再起動の試験 U4 NFR2.5 ✓
    NF-R13 手動の確定と自動確定が同時に起きても、週の結果と費用は一度だけ計上される（sessions.version と week_results の主キー） 2 プロセスの並行テスト FR-09、FR-18 新
    NF-R14 共同担当の同時の保存で、受理済みの書き込みを失わず、拒否された側へ最新値と保存者を返す 並行のテスト FR-16 新

    セキュリティ・プライバシー要件¶

    ID 要件 測定方法 出典 v1 の状態
    NF-S1 進行役の資格と復帰資格は、128 ビット以上の暗号論的乱数とし、生の値は発行時に一度だけ返す 乱数長と一意性のテスト U1 NFR3.1、NFR-06 ✓（256 ビット）
    NF-S2 資格は、HttpOnly、Secure、SameSite=Strict の Cookie でだけ送り、URL、ログ、監査、出力に含めない ヘッダーのテスト U1 NFR3.2、U5 NFR3.12 ✓
    NF-S3 資格は、鍵付きダイジェストと鍵の版だけを保存し、定数時間で比較する。鍵は複数の版を同時に保持し、ローテーション後も旧版の資格を期限まで検証できる。本番では鍵の設定を必須とし、未設定なら起動に失敗する 保存内容の検査、起動のテスト U1 NFR3.3、ADR-009 △（v1 は、本番の鍵が固定の開発用の値。鍵の版が無い）
    NF-S4 すべての資格（進行役、復帰、観察用の招待、ブラウザセッション）に、有効期限と失効を持たせる。進行役は、資格を失効・再発行できる。 有効期間の既定値は、運営者と合意して決める（ブラウザセッション 24 時間、復帰資格 30 日、進行役の資格はゲームの保持期間内 など）。終了後の失効の扱いも合意する 信頼できる時計での境界テスト U1 NFR3.4、ADR-009 ✗（v1 は、進行役の資格に期限と失効が無く、復帰資格は 30 日）
    NF-S5 すべての読み取り・書き込み・SSE の購読で、ゲーム、セッション、役割、操作の認可を、サーバー側で検査する 認可の行列テスト NFR-06、U1 NFR3.5 ✓
    NF-S6 参加者への応答とイベントは、自分の役割の状態だけを含み、他の役割、将来の需要、資格を、直列化の前に除く 否定のテスト U1 NFR3.6、U5 NFR3.14 ✓
    NF-S7 参加コードは参加先の発見にだけ使い、進行役の操作や状態参照の資格として扱わない 認可のテスト U1 NFR3.7 ✓
    NF-S8 変更系のリクエストは、Origin（または Referer）を検査して外部のオリジンを拒否し、版と冪等キーを要求する CSRF の否定テスト U5 NFR3.15、3.16 ✓
    NF-S9 セキュリティヘッダー（CSP、HSTS、nosniff、制限的な Referrer-Policy）を、CloudFront と API の両方で設定する ヘッダーの検査 U3 NFR3.5、U5 NFR3.16、ADR-011 ✗
    NF-S10 入力はスキーマで検証し、数量、ペイロード、リクエストの大きさに上限を設ける 境界値と悪意のある入力のテスト U1 NFR3.9 ✓
    NF-S11 参加、復帰、観察用の招待での参加のエンドポイントに、専用のレート制限を設け、連続の失敗を記録する。実効の上限が、タスク数で増えないようにする 総当たりのテスト U2 NFR11.6 △（v1 は IP 単位の全体の制限のみで、プロセス内）
    NF-S12 復帰の失敗は、資格の存在・期限・削除の状態を区別しない応答とする 応答のテスト U2 NFR11.5 ✓
    NF-S13 CI で依存関係、秘密情報、静的解析（SAST）を検査し、Critical と High はリリースを止める CI の記録 U1 NFR3.11 ✗
    NF-S14 収集する個人情報は表示名だけとし、監査、ログ、テレメトリ、出力に、表示名と資格を含めない スキーマとデータフローのレビュー、ログの走査 NFR-07、U1 NFR4.1、4.2 △（データは表示名のみ。ログ自体が出ない）
    NF-S15 保存時と通信時に暗号化する（データベースは KMS、通信は HTTPS）。TLS は 1.2 以上とする（独自ドメインと ACM の証明書） 設定の検査 U3 NFR3.5、U4 NFR3.4 △（v1 は既定の証明書で、最低版を指定できない）
    NF-S16 保持期間は運営者が設定でき（1〜3650 日、既定 90 日）、期限後に削除する。削除は、games のカスケード削除で、削除後に、game_id 列を持つすべての表に行が残らない。 削除の受領記録は、ゲームを特定できない形で 1 年残す。バックアップに残る期間（7 日）を、保持方針に明記する 保持のテスト、information_schema を使った網羅の検査 NFR-07、U4 NFR4.1、ADR-007 △（v1 は、outbox_events と idempotency_records が削除対象外）
    NF-S17 エクスポートの取得は、進行役だけで、毎回認可し、取得用の参照は 15 分で失効する 認可の行列テスト U3 NFR3.4 △（進行役のみ、毎回認可は実装済み。15 分の失効は未確認）
    NF-S18 観察者は、読み取り専用で、役割別の在庫・受注残・意思決定値と将来の需要を取得できない。観察用の招待は、参加コードと別の値で、有効期間と失効を持つ 認可の行列テスト FR-17、BR-17 新
    NF-S19 観察用の招待・参加コード・復帰資格の総当たりを、専用のレート制限と監視で検知する 総当たりのテスト、アラート NFR-06 新

    v1 からの変更（差分への対応）¶

    v1 の差分（12 件）への対応です。すべて v2 の要件として引き継ぎました。

    # v1 の差分 v2 の対応
    1 アプリがログを一切出力しない。メトリクスも無い NF-O1〜NF-O5。構造化ログ（Pino）、エラーの記録、メトリクス（EMF）を最初から実装する
    2 本番の資格の鍵が、固定の開発用の値 NF-S3。本番では必須。未設定なら起動に失敗する。鍵に版を持たせる（ADR-009）
    3 資格の有効期間が設計と異なる（進行役は期限なし） NF-S4。すべての資格に期限と失効。進行役の失効・再発行
    4 セキュリティヘッダーが無い。TLS の最低版を指定できない NF-S9、NF-S15。CloudFront と API でヘッダーを付け、独自ドメインで TLS 1.2 以上（ADR-011）
    5 CI に依存関係・秘密情報・SAST の検査が無い NF-S13。CI に加える（ADR-012）
    6 可用性の SLI と停止の検知（1 分以内）が無い NF-R1、NF-R2、NF-O4。合成監視とアラームを設計に含める（インフラ）
    7 性能の主要な目標が未測定 NF-P1〜NF-P3、NF-P5。実 DB の負荷試験と、確定から反映までの計測を、夜間に実行して記録する（テスト戦略）
    8 復元の訓練が無い。保存途中の障害の注入テストも無い NF-R3〜NF-R5、NF-R8。復元の訓練を、四半期とリリース前に行う。障害の注入は DB 統合に含める
    9 冪等記録の保持が、設計 24 時間に対し実装 30 日 NF-R6。24 時間に統一（idempotency_records は games へのカスケードで削除される）
    10 復帰エンドポイント専用のレート制限が無い。制限がプロセス内 NF-S11、NF-S19。参加・復帰・招待の専用の制限と、状態の共有
    11 数値目標が、運営者と合意されていない 引き続き、合意を取る（下記の未決事項）
    12 Unit 間で数値が一部食い違っていた 全体の可用性 99.5%、基準 15 ゲーム、拡張目標 25 ゲームに統一済み
