## Q3. [プロダクト] 優先度（MoSCoW）の付け方

各ストーリーに、Must Have（必須）、Should Have（重要）、Could Have（あれば良い）、Won't Have（今回はしない）を付けます。ここでの優先度は、後の Delivery Planning で最小の実用範囲を決めるときの材料になります。どう付けますか？

A. 要件定義書の「受入れの判断基準」に関わるものを Must にする。補助的なもの（結果の出力、保持期限後の削除、代理入力）は Should にする
B. v1 の要件はすべて Must にする
C. 薄い一通り（ゲーム作成から 1 週の確定と状態表示まで）に必要なものだけを Must にし、ほかは Should または Could にする

## Q5. [プロダクト] 進行中の役割の再割当て

要件では、進行中は役割の割当てを変えない（FR3.2）一方、復帰のために進行役が割当てを変えられる（FR12.2）とあり、矛盾しています。ブラウザの token を失った参加者や、途中から入る人は、どう扱いますか？

A. 進行中も、進行役は「同じ役割の担当者の入れ替え」だけ許す。役割そのものの増減や、他の役割への移動は許さない

C. 進行中でも、進行役は自由に割当てを変えられる
