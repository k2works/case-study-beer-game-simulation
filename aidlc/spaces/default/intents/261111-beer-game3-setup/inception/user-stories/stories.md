# ユーザーストーリー

`requirements.md`（FR1〜FR15、NFR1〜NFR11）を、利用の流れで分けたストーリーです（Q2）。優先度は MoSCoW で、要件定義書の「受入れの判断基準」に関わるものを Must、補助的なものを Should としています（Q3）。最小の実用範囲は、後の Delivery Planning で決めます。

ペルソナは `personas.md` を参照してください（P1 参加者、P2 進行役、P3 観察者、P4 運営者）。上流の資料は `business-overview.md`、`component-inventory.md`、`team-practices.md` です。

## グループ 1 ゲームの準備と薄い一通り

最初の動くコードは、1 ゲーム、4 役割、1 週分を確定して状態を表示する薄い一通りです（`team-practices.md`）。US1.1〜US1.5 がその対象です。

### US1.1 進行役がゲームを作成する

- ペルソナ: P2 進行役
- 優先度: Must Have
- ストーリー: 進行役として、週数、需要系列、初期条件を設定してゲームを作成したい。参加者を同じ条件で遊ばせるため。
- 依存: なし
- 受入条件:
  - AC1.1.1 Given 進行役がゲーム作成画面を開いている / When 週数に 0 または 51 を入力して保存する / Then 範囲外として拒否し、1〜50 を案内する。入力済みの他の項目は残る
  - AC1.1.2 Given 週数 50 のゲーム設定 / When 需要系列を 49 週分だけ入力して保存する / Then 長さ不一致として拒否する
  - AC1.1.3 Given 進行役が初期在庫に負数を入力する / When 保存する / Then 拒否し、非負の整数を案内する。設定画面には、遅延の週数を変える項目はなく、初期パイプライン数量の項目がある
  - AC1.1.4 Given 正しい設定 / When 保存する / Then ゲームが作られ、推測困難な参加コードと進行役用コードが発行される
  - AC1.1.5 Given 参加コードだけを持つ人 / When 週確定などの進行役の操作を要求する / Then 権限がないとして拒否される
- INVEST: 独立して作成・試験できる。作成だけで価値（後続の入口）がある

### US1.2 参加者が参加コードでゲームに参加する

- ペルソナ: P1 参加者
- 優先度: Must Have
- ストーリー: 参加者として、参加コードと表示名でゲームに参加したい。アカウントを作らずにすぐ始めるため。
- 依存: US1.1
- 受入条件:
  - AC1.2.1 Given 準備中のゲームの有効な参加コード / When 参加者が表示名を入力して参加する / Then ロビーの参加者一覧に表示名が加わる
  - AC1.2.2 Given 終了済みのゲームの参加コード / When 参加を試みる / Then 「終了済み」という理由で拒否される
  - AC1.2.3 Given 進行中のゲームの参加コード / When 新しい人が参加を試みる / Then 「進行中のため参加できない」という理由で拒否される
  - AC1.2.4 Given 無効なコード / When 参加を試みる / Then 拒否され、理由が表示される
- INVEST: US1.1 の出力を入力として試験できる

### US1.3 進行役が役割を割り当てて開始する

- ペルソナ: P2 進行役
- 優先度: Must Have
- ストーリー: 進行役として、4 役割を重複なく割り当ててゲームを開始したい。全役割が揃った状態で始めるため。
- 依存: US1.2
- 受入条件:
  - AC1.3.1 Given 4 役割のうち 1 つが未割当て / When 進行役がゲームを開始する / Then 開始できず、未割当ての役割を示す
  - AC1.3.2 Given ゲームが準備中 / When 進行役が参加者を別の役割へ移す / Then 変更できる
  - AC1.3.3 Given 4 役割がすべて割り当て済み / When 進行役が開始する / Then ゲームは進行中になり、第 1 週が始まり、初期状態が固定される
- INVEST: 独立して試験できる

### US1.4 参加者が自分の役割の状況を見て発注数を入力する

- ペルソナ: P1 参加者
- 優先度: Must Have
- ストーリー: 参加者として、自分の役割の在庫・受注残・入荷・受注を見て、発注数（工場は生産要請数）を入力したい。限られた情報で意思決定を体験するため。
- 依存: US1.3
- 受入条件:
  - AC1.4.1 Given 小売店の参加者 / When 他役割の在庫を取得する要求を直接送る / Then 拒否され、値は返らない
  - AC1.4.2 Given 発注数の入力欄 / When 2.5、-1、空欄、「abc」を入力する / Then いずれも拒否され、入力した他の値は残る
  - AC1.4.3 Given 同じ入力欄 / When 0 を入力する / Then 受け付ける
  - AC1.4.4 Given 第 5 週で発注数 10 を入力済みで、まだ週が確定していない / When 12 に変更する / Then 12 が有効になる
- INVEST: 役割別の情報制約を、画面と応答の両方で試験できる

### US1.5 週を確定して状態を表示する

- ペルソナ: P2 進行役
- 優先度: Must Have
- ストーリー: 進行役として、4 役割の入力が揃った週を確定し、新しい状態を表示したい。計算と遅延を自動で進め、単純ミスを避けるため。
- 依存: US1.4
- 受入条件:
  - AC1.5.1 Given 第 5 週で小売店の発注数だけが未入力 / When 週の確定を要求する / Then 拒否され、未入力の役割として小売店を示す
  - AC1.5.2 Given 第 5 週で 4 役割すべての入力が済み、参加者が入荷数の確認の操作をしていない / When 週の確定を要求する / Then 確定できる
  - AC1.5.3 Given 前週末在庫 12、当週入荷 4、前週末受注残 0、当週受注 20 / When 週を確定する / Then 出荷 16、週末在庫 0、週末受注残 4
  - AC1.5.4 Given 前週末在庫 12、当週入荷 0、前週末受注残 0、当週受注 4 / When 週を確定する / Then 出荷 4、週末在庫 8、週末受注残 0
  - AC1.5.5 Given 第 3 週に工場が一次卸へ出荷した / When 第 4 週を確定する / Then 一次卸の入荷にはまだ加わらず、第 5 週に加わる
  - AC1.5.6 Given 第 3 週に小売店が発注した / When 第 4 週を確定する / Then 二次卸の受注にはまだ加わらず、第 5 週に加わる
  - AC1.5.7 Given 工場の週 / When 受注のステップに至る / Then 工場は一次卸からの注文を受注として扱い、番号は他役割と同じになる
  - AC1.5.8 Given 第 5 週の確定が完了している / When 同じ週の確定がもう一度届く / Then 状態は変わらず、前回と同じ結果を返す
  - AC1.5.9 Given 週末在庫 8、週末受注残 4 / When 週を確定する / Then その週の費用は $8.00 になり、累積費用に加わる
- INVEST: 計算、遅延、冪等性を、既知系列の golden test で検証できる

### US1.6 進行役がキット準拠とカスタムを区別して設定する

- ペルソナ: P2 進行役
- 優先度: Must Have
- ストーリー: 進行役として、キット準拠のプリセットでゲームを作り、設定を変えたゲームは「カスタム」と区別したい。教材の忠実性を保ち、複数チームを同じ条件で比較するため。
- 依存: US1.1
- 受入条件:
  - AC1.6.1 Given 需要系列を指定せずにゲームを作成する / When 保存する / Then 仮の既定の系列が入り、ゲームは「カスタム」と表示される
  - AC1.6.2 Given JSD の既定の需要系列が未確定の間 / When キット準拠のプリセットで作成する / Then ゲームは「カスタム」と表示され、キット準拠とは表示されない
  - AC1.6.3 Given 試験用に、プリセットの全項目と一致する設定を与えた自動試験 / When 判定する / Then 「キット準拠」と判定される
  - AC1.6.4 Given 週数を 30 週に変更したゲーム / When 結果を出力する / Then 「カスタム」の区別が出力に残る
  - AC1.6.5 Given キット準拠のプリセットで作成した直後のゲーム / When 第 1 週と第 2 週を確定する / Then 各役割の入荷は、配送遅延の枠に最初から入っている数量（4）になり、第 3 週の入荷から、第 1 週以降の出荷が加わる
- INVEST: 需要系列が未確定でも、試験用の設定で検証できる（`requirements.md` の未確定事項）

## グループ 2 プレイの続き

### US2.1 小売店だけが当週の顧客需要を見る

- ペルソナ: P1 参加者（小売店）
- 優先度: Must Have
- ストーリー: 小売店の参加者として、当週の顧客需要だけを見たい。将来の需要を知らないまま意思決定する体験をするため。
- 依存: US1.4
- 受入条件:
  - AC2.1.1 Given 第 3 週のプレイ中 / When 小売店が需要を見る / Then 第 3 週までの値だけが見え、第 4 週以降は見えない
  - AC2.1.2 Given 小売店以外の参加者 / When 顧客需要を取得する要求を送る / Then 拒否される
- INVEST: 独立して試験できる

### US2.2 同じ役割を複数人で共同担当する

- ペルソナ: P1 参加者
- 優先度: Should Have
- ストーリー: 参加者として、同じ役割を仲間と共同で担当したい。人数が多い研修でも、役割を埋めて参加するため。
- 依存: US1.3
- 受入条件:
  - AC2.2.1 Given 1 つの役割に 2 人が割り当てられている / When 2 人が別々の発注数を入力する / Then 役割の入力として、最後に確定した 1 つの値だけが扱われ、もう一方の人の画面には、置き換わったことが示される
  - AC2.2.2 Given 1 つの役割に 4 人が割り当てられている / When 5 人目を割り当てようとする / Then 拒否される
- INVEST: 後勝ちは前提（`requirements.md` の前提）に基づく

### US2.3 同じ表示名の参加者を区別する

- ペルソナ: P1 参加者
- 優先度: Should Have
- ストーリー: 参加者として、同じ表示名の人がいても参加したい。名前の重複で締め出されないため。
- 依存: US1.2
- 受入条件:
  - AC2.3.1 Given 「太郎」という表示名の参加者がいる / When 別の人が「太郎」で参加する / Then 2 人とも参加でき、画面で区別できる
- INVEST: 小さく独立している

### US2.4 週確定は途中で失敗しても部分更新を残さない

- ペルソナ: P2 進行役
- 優先度: Must Have
- ストーリー: 進行役として、週の確定が途中で失敗しても、ゲームが壊れないでほしい。二重計上や欠落なく続けるため。
- 依存: US1.5
- 受入条件:
  - AC2.4.1 Given 週確定の処理の途中で保存に失敗した / When 復旧後に状態を取得する / Then 確定前の状態のままで、確定済みの一部は残らない
  - AC2.4.2 Given 進行役 2 人の端末から同時に確定が届く / When 処理する / Then 週は一度だけ確定される
  - AC2.4.3 Given 発注数の入力の送信が 2 回届いた / When 処理する / Then 入力は 1 件として扱われる
- INVEST: 障害を注入して試験できる

### US2.5 進行役がゲームを一時停止・再開・終了する

- ペルソナ: P2 進行役
- 優先度: Must Have
- ストーリー: 進行役として、ゲームを一時停止、再開、終了したい。振り返りや休憩を挟みつつ、終了週で確実に終えるため。
- 依存: US1.3
- 受入条件:
  - AC2.5.1 Given ゲームが一時停止中 / When 参加者が発注数を確定する / Then 拒否され、一時停止中であることが示される。閲覧はできる
  - AC2.5.2 Given ゲームが一時停止中 / When 進行役が再開する / Then 進行中に戻り、確定操作ができる
  - AC2.5.3 Given ゲームが終了した / When 参加者が入力を試みる / Then 拒否される
  - AC2.5.4 Given 終了週を確定した / When 確定が完了する / Then ゲームは自動で終了する
- INVEST: 状態遷移で試験できる

### US2.6 進行役が役割の担当者を入れ替える

- ペルソナ: P2 進行役
- 優先度: Must Have
- ストーリー: 進行役として、進行中でも、同じ役割の担当者を入れ替えたい。参加者が token を失ったり、途中で交代したりしても、ゲームを続けるため。
- 依存: US1.3
- 受入条件:
  - AC2.6.1 Given ゲームが進行中 / When 進行役が小売店の担当者を別の人に入れ替える / Then 入れ替えられ、以前の担当者の復帰用 token は無効になり、役割の在庫・受注残・履歴は変わらない
  - AC2.6.2 Given ゲームが進行中 / When 進行役が小売店の担当者を工場へ移そうとする / Then 拒否される
  - AC2.6.3 Given ゲームが一時停止中 / When 進行役が同じ役割の担当者を入れ替える / Then 入れ替えられる
- INVEST: 独立して試験できる

### US2.7 進行役が不在の役割に代わって入力する

- ペルソナ: P2 進行役
- 優先度: Should Have
- ストーリー: 進行役として、不在の役割に代わって入力したい。参加者が欠けても、週を進めるため。
- 依存: US1.4
- 受入条件:
  - AC2.7.1 Given 工場の参加者が不在 / When 進行役が工場の生産要請数 8 を代理入力する / Then 値が入力され、履歴に進行役・工場・時刻・8 が残る
- INVEST: 小さく独立している（自動補充の戦略は対象外）

### US2.8 進行役が進行を管理する

- ペルソナ: P2 進行役
- 優先度: Should Have
- ストーリー: 進行役として、4 役割の入力完了状況と各役割の現在の状態を見たい。誰の入力を待っているか分かり、代理入力の判断ができるため。
- 依存: US1.4
- 受入条件:
  - AC2.8.1 Given 進行役が進行管理画面を開いている / When プレイ中 / Then 4 役割の入力完了状況と各役割の現在の状態が見える
  - AC2.8.2 Given 参加者が自分の役割の画面を開いている / When 進行管理画面の URL を直接要求する / Then 進行役用コードがないため拒否される
- INVEST: 小さく独立している

### US2.9 観察者が入力できずに進行を見る

- ペルソナ: P3 観察者
- 優先度: Should Have
- ストーリー: 観察者として、意思決定を妨げずに進行を見たい。参加者の学習を損なわずに、状況を把握するため。
- 依存: US1.5
- 受入条件:
  - AC2.9.1 Given 観察者が観察画面を開いている / When プレイ中 / Then チーム全体の集計値と現在週が見え、役割別の在庫・受注残・意思決定値は見えない
  - AC2.9.2 Given 観察者 / When 発注数を入力する要求を送る / Then 拒否される
- INVEST: 公開範囲は前回の決定（チーム全体の値に限る）に従う

## グループ 3 中断と復帰

### US3.1 中断したゲームを確定済みの週から復元する

- ペルソナ: P2 進行役
- 優先度: Must Have
- ストーリー: 進行役として、中断したゲームを、確定済みの週から復元したい。サービスが止まっても、積み上げた結果を失わないため。
- 依存: US1.5
- 受入条件:
  - AC3.1.1 Given 第 10 週まで確定したゲーム / When サービスが再起動して復元する / Then 第 10 週の状態が再起動前と一致し、第 11 週から続けられる
  - AC3.1.2 Given 第 5 週で小売店が発注数 10 を入力済みで未確定 / When サービスが再起動する / Then 再起動後も小売店の入力は 10 のまま残っている
- INVEST: 在庫、受注残、遅延、履歴、費用の一致を検証できる

### US3.2 参加者が切断後に同じ役割へ戻る

- ペルソナ: P1 参加者
- 優先度: Must Have
- ストーリー: 参加者として、回線が切れても、同じ役割に戻りたい。個人情報を渡さずに、入力を失わないため。
- 依存: US1.4
- 受入条件:
  - AC3.2.1 Given 参加者が参加した / When ブラウザを閉じて同じブラウザで再度開く / Then 同じ参加者・同じ役割として復帰できる
  - AC3.2.2 Given 参加者が 30 分間切断された / When 同じブラウザで再接続する / Then 確定済みのデータは失われず、同じ役割に戻れる。入力済みの未確定値も残る
  - AC3.2.3 Given 最後の操作から 24 時間を超えた復帰用 token / When その token で再接続する / Then 拒否され、進行役による入れ替えが必要と案内される
  - AC3.2.4 Given 参加者が復帰用 token を失った / When 進行役が同じ役割の担当者の入れ替えをする / Then 新しい token で同じ役割に戻れる
- INVEST: 測定値（30 分、24 時間）は仮の値

## グループ 4 振り返り

### US4.1 終了後に全役割の時系列を比較する

- ペルソナ: P1 参加者
- 優先度: Must Have
- ストーリー: 参加者として、終了後に需要と全役割の時系列を比較したい。自分の判断が全体に与えた影響と、増幅の過程を理解するため。
- 依存: US1.5
- 受入条件:
  - AC4.1.1 Given ゲームが終了した / When 参加者が結果画面を開く / Then 全役割の需要、注文、在庫、受注残、出荷、費用の時系列が見える
  - AC4.1.2 Given 終了したゲーム / When 結果画面で「受注残」を選ぶ / Then 4 役割の受注残が同じ週の軸で重なって表示される
  - AC4.1.3 Given 結果画面の複数の系列 / When 色を区別できない人が見る / Then 色だけに頼らず、系列を区別できる（線種・印・凡例）
  - AC4.1.4 Given プレイ中のゲーム / When 参加者が結果画面を要求する / Then 他役割の時系列は開示されない
- INVEST: 振り返りの中核

### US4.2 進行役が結果を CSV と JSON で出力する

- ペルソナ: P2 進行役
- 優先度: Should Have
- ストーリー: 進行役として、ゲーム設定と全週の記録を出力したい。複数チームの比較や、振り返りの資料に使うため。
- 依存: US4.1
- 受入条件:
  - AC4.2.1 Given 終了したゲーム / When CSV で出力する / Then 週ごと・役割ごとに入荷、受注、出荷、在庫、受注残、発注または生産要請、費用の列があり、キット準拠かカスタムかの区別が含まれる
  - AC4.2.2 Given 同じゲーム / When JSON で出力する / Then CSV と同じ数値が一致する
  - AC4.2.3 Given 表示名にカンマと改行を含む参加者 / When CSV で出力する / Then 行が崩れず、値は元のまま読み戻せる
- INVEST: 小さく独立している

## グループ 5 運営と品質

### US5.1 運営者が保持期間を設定し、期限後にデータが削除される

- ペルソナ: P4 運営者
- 優先度: Should Have
- ストーリー: 運営者として、保持期間を設定し、期限後にデータが削除されるようにしたい。個人情報を持ち続けないため。
- 依存: US2.5
- 受入条件:
  - AC5.1.1 Given 終了から 31 日が経過し、保持期間を設定していないゲーム / When 削除の処理が動く / Then ゲームのデータは削除され、参加コードは無効になる
  - AC5.1.2 Given 保持期間を 7 日に設定したゲーム / When 終了から 8 日が経つ / Then 設定の期間に従って削除される
  - AC5.1.3 Given 最後の操作から 30 日、終了していないゲーム / When 自動終了の処理が動く / Then ゲームは終了し、その時点から保持期間が数えられる
- INVEST: 時刻を注入して試験できる（自動終了の 30 日は仮の値）

### US5.2 同じ入力から常に同じ結果が再現される

- ペルソナ: P2 進行役
- 優先度: Must Have
- ストーリー: 進行役として、同じ初期状態と意思決定系列から、常に同じ結果が出てほしい。複数チームを公平に比較し、教材として信頼できるようにするため。
- 依存: US1.5
- 受入条件:
  - AC5.2.1 Given 既知の初期状態と意思決定系列 / When 2 回実行する / Then 50 週すべての在庫、受注残、注文、出荷、遅延、費用が両方とも期待値と一致する
- INVEST: 既知系列の golden test で検証する

### US5.3 通常負荷で応答し、15 チームを同時に支える

- ペルソナ: P1 参加者
- 優先度: Must Have
- ストーリー: 参加者として、入力や週の確定がすぐ反映されてほしい。待たされずにテンポよく進めるため。
- 依存: US1.5
- 受入条件:
  - AC5.3.1 Given 通常負荷（15 チームの同時接続、各チーム 1 分あたり 1 週の確定）/ When 10 分間の負荷試験を行う / Then 入力確定の 95 パーセンタイルが 1 秒以内、週確定後の画面反映が 2 秒以内
- INVEST: 測定値は仮の値

### US5.4 操作権限をサーバー側で検証する

- ペルソナ: P1 参加者
- 優先度: Must Have
- ストーリー: 参加者として、他のゲームや他の役割の情報を触られないでほしい。公平な学習のため。
- 依存: US1.1
- 受入条件:
  - AC5.4.1 Given 他のゲームの役割の識別子 / When その役割の入力を送る / Then 拒否される
  - AC5.4.2 Given 同じ接続元が 1 分間に 11 回、無効なコードで参加を試みた / When 11 回目を送る / Then 一時的に拒否される
- INVEST: 試行回数の制限は仮の値

### US5.5 すべての画面をキーボードで操作できる

- ペルソナ: P1 参加者
- 優先度: Must Have
- ストーリー: 参加者として、キーボードだけでも操作でき、色に頼らず読めるようにしたい。誰でも参加できるため。
- 依存: US1.5
- 受入条件:
  - AC5.5.1 Given 任意の画面 / When キーボードだけで、ゲーム作成から週の確定まで操作する / Then すべて完了できる
  - AC5.5.2 Given 任意の画面の文字と背景 / When コントラスト比を測る / Then 通常の文字で 4.5:1 以上
- INVEST: 測定値（WCAG 2.2 AA）は仮の値

### US5.6 設定と操作の履歴を追跡できる

- ペルソナ: P2 進行役
- 優先度: Should Have
- ストーリー: 進行役として、設定、役割変更、代理入力、週確定、停止、再開、終了の履歴を追いたい。誰が何をしたかを、後から説明できるため。
- 依存: US1.5
- 受入条件:
  - AC5.6.1 Given 設定変更、役割変更、代理入力、週確定、停止、再開、終了を行ったゲーム / When 履歴を取得する / Then 7 種類の操作それぞれに、誰が、いつ、何をしたかが残っている
- INVEST: 小さく独立している

### US5.7 専用ソフトなしで、日本語の画面を主要なブラウザで使える

- ペルソナ: P1 参加者
- 優先度: Must Have
- ストーリー: 参加者として、専用ソフトを入れずに、日本語の画面をブラウザで使いたい。準備の手間なく参加するため。
- 依存: US1.5
- 受入条件:
  - AC5.7.1 Given Chrome、Edge、Firefox、Safari の最新 2 世代 / When ゲーム作成から週の確定までの主要な操作を行う / Then いずれでも完了できる
  - AC5.7.2 Given 任意の画面と出力 / When 表示を確認する / Then 日本語で表示される（英語への切り替えはない）
- INVEST: ブラウザ名は仮の値
