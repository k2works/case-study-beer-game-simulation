# ペルソナ

beer-game3 の利用者を 4 つのペルソナに分けます（Q1）。参加者は役割（工場・一次卸・二次卸・小売店）で分けず、役割ごとの違いは各ストーリーの受入条件で表します。

## 優先順位

1. 参加者（主たる利用者。ゲームの価値は参加者の体験で決まる）
2. 進行役（ゲームを成立させる運営の中心）
3. 観察者（意思決定を妨げずに進行を把握する）
4. 運営者（画面を持たず、設定として保持期間を扱う）

## P1 参加者

- 役割: ビールゲームのサプライチェーンの 1 役割（工場・一次卸・二次卸・小売店のいずれか）を担当する。1 つの役割を複数人が共同で担当することもある（最大 4 人）
- 目標:
  - 自分の役割に見える情報だけで、発注数（工場は生産要請数）を決める
  - 12 ステップの計算ミスをせずに、週を進める
  - 終了後に、自分の判断がチーム全体に与えた影響を理解する
- 悩み:
  - 盤面の操作や計算の単純ミス
  - 他の役割が見えず、増幅の原因が分からない
  - 回線が切れたときに、入力が失われないか不安
- 技術への慣れ: 中程度（ブラウザで操作できる）
- 利用頻度: 学習セッションの間（1 ゲームで数時間から数日）
- 関係: 進行役の合図で進み、観察者に見られる

## P2 進行役

- 役割: ゲームの作成、役割の割当て、開始、週の確定、停止・再開・終了、代理入力を行う。学習支援（振り返り）が本務
- 目標:
  - ルールの説明より学習支援に集中する
  - 複数チームを同じ条件で比較する
  - 振り返りで Bullwhip Effect の発生過程を説明する
- 悩み:
  - 参加者の回線切れや不在で、進行が止まる
  - 設定の違うゲームを、キット準拠と取り違える
- 技術への慣れ: 中程度から高い
- 利用頻度: セッションごと（複数ゲームを並行することもある）
- 関係: 参加者を導き、観察者に公開範囲を許可する

## P3 観察者

- 役割: 意思決定を妨げずに進行を見る。入力はできない
- 目標: 進行状況を把握する。公開された範囲で、状況を見守る
- 悩み: 見せてよい範囲を超えて情報が見えてしまうと、参加者の学習を損ねる
- 技術への慣れ: 中程度
- 利用頻度: セッションの間
- 関係: 進行役が許可した、チーム全体の集計値だけを見られる（役割別の非公開情報は逆算できない）

## P4 運営者

- 役割: アプリケーションを運用する人。画面を持たず、保持期間の既定など、アプリケーションの設定を指定する
- 目標: 個人情報を持ち続けず、保持期限を過ぎたデータが削除される
- 悩み: 放置されたゲームがデータを占有し続ける
- 技術への慣れ: 高い
- 利用頻度: 設定時と障害時
- 関係: 進行役や参加者のデータの保持期間を決める
