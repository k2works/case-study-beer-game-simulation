## 複数の Unit にまたがる関心事

ストーリーを割り当てた Unit のほかに、次の関心事が複数の Unit にまたがります。実装するのは上の表の Unit で、ほかの Unit は、その上に加わるか、自分の範囲で同じ検査を通します。

| 関心事 | 実装する Unit | ほかの Unit の関わり |
| :--- | :--- | :--- |
| 週確定の冪等性（AC1.5.8） | U1（US1.5） | U2 が同時実行と障害の注入の試験で強める（US2.4） |
| 役割別の情報制約（AC1.4.1） | U1（US1.4） | U4 が小売店だけの需要、観察者、サーバー側の権限の検証で仕上げる |
| 権限の検証（進行役の操作の拒否、AC1.1.5） | U1（US1.1） | U3 の運営操作と U5 の出力の取得も、同じ権限の検証を通す |
| キーボード操作とコントラスト（AC5.5.1、AC5.5.2） | U6（US5.5） | U1〜U5 の画面は、自分の画面について同じ検査を通す |
| 日本語のみの表示（AC5.7.2） | U6（US5.7） | U1〜U5 の画面と出力は、日本語で表示する |
| 履歴の記録（AC5.6.1） | U3（US5.6） | 履歴の仕組みは U3 が作る。U1 で作る設定と週確定の履歴も、U3 の中で足す（U1 は履歴に依存しない） |

## Unit 内の実装の順

実装の順は、Unit の中の依存の順を示します。Unit 間の順は Delivery Planning が決めます。

| Unit | Unit 内の実装の順 |
| :--- | :--- |
| U1 | US1.1 → US1.2 → US1.3 → US1.4 → US1.5（各ストーリーの前依存に従う） |
| U2 | US1.6 → US5.2 → US2.4（種別の判定、再現性の golden test、障害と同時実行の順に重ねる） |
| U3 | US2.5 → US2.6 → US2.7 → US2.8 → US5.6、US2.2、US2.3（状態遷移を先にし、そのほかを重ねる） |
| U4 | US5.4 → US2.1 → US2.9 → US3.2 → US3.1（権限の検証を先にし、復帰と復元を重ねる） |
| U5 | US4.1 → US4.2 → US5.1（比較表示を先にし、出力、保持と削除を重ねる） |
| U6 | US5.5 → US5.7 → US5.3（画面の検査を先にし、負荷試験を最後にする） |

## カバレッジの確認

- 割り当てたストーリーは 26 件で、`stories.md` の US1.1〜US5.7 のすべてを網羅している。割り当てのないストーリーはない。
- すべての Unit に、1 件以上のストーリーがある（U1 が 5 件、U2 が 3 件、U3 が 7 件、U4 が 5 件、U5 が 3 件、U6 が 3 件）。
- 1 件のストーリーが複数の Unit に重複して割り当てられていることはない。
- 機械可読の対応は `traceability.json` にある。
