# 操作の仕様

`mockups.md` の画面について、利用者の操作の流れと、主な部品の状態・振る舞い・アクセシビリティを定めます。部品の書き方は、部品仕様のひな形に従います。対応するストーリーは `stories.md`、要件は `requirements.md` を参照してください。

## 利用の流れ

### 流れ 1 ゲームの準備から開始まで（薄い一通りの入口）

- 利用者: 進行役、参加者
- 開始のきっかけ: 進行役が S1 を開く
- 手順:
  1. S1 でゲームの設定を入力し「作成する」を押す。システムは参加コードと進行役用コードを表示する
  2. 進行役は参加コードを参加者に伝える。参加者は S0 で参加コードと表示名を入力し「参加する」を押す。システムは S2 に移す
  3. 進行役は S2 で役割を割り当てる。各役割に 1 人以上がそろうと、開始ボタンが押せるようになる
  4. 進行役が「ゲームを開始する」を押す。システムは初期状態を固定し、全員の画面を S3 に移す
- 成功の結果: 全員が第 1 週の S3 を見る
- 誤りの経路:
  - 無効なコード、終了済み、進行中 -> S0 の欄の下に理由 -> 正しいコードを入れ直す
  - 役割の不足 -> S2 に不足の役割 -> 割り当てる

### 流れ 2 1 週のプレイ

- 利用者: 参加者、進行役
- 手順:
  1. 参加者は S3 で今週の状況（入荷、受注、在庫、受注残）を確認する
  2. 参加者は発注数（工場は生産要請数）を入力する。値は入力した時点で保存される。確定前は変更できる
  3. 4 役割の入力がそろうと、進行役の S4 で確定ボタンが押せるようになる
  4. 進行役が確認で「確定する」を選ぶ。システムは週を原子的に確定し、全員の S3 を次の週に更新する
- 誤りの経路:
  - 入力の誤り（小数、負数、空欄、文字）-> 欄の下に理由 -> 入れ直す
  - 確定の失敗 -> 確定前のまま -> 進行役が再実行する
  - 不在の役割 -> 進行役が S4 で代理入力する
  - 回線の切断 -> 帯で知らせる -> 復帰用 token で自動復帰（失った場合は進行役が担当者を入れ替える）

### 流れ 3 終了と振り返り

- 手順:
  1. 終了週を確定すると、ゲームは自動で終了する。進行役は S4 の「終了」で途中終了もできる
  2. 全員が S6 で、指標と表示（グラフ・表）を切り替えて比較する
  3. 進行役は CSV または JSON で出力する

### 流れ 4 担当者の入れ替え

- 利用者: 進行役
- 手順: S4 で役割を選び「担当者の入れ替え」-> 同じ役割の中で新しい担当者を選ぶ -> 確認 -> 入れ替え。以前の担当者の復帰用 token は無効になる
- 誤りの経路: 他の役割への移動や、役割の増減は選べない（選択肢に出さない）

## 部品の仕様

### 発注数の入力欄

| 項目 | 値 |
| :--- | :--- |
| 部品 | 発注数の入力欄 |
| 説明 | 発注数（工場は生産要請数）を、非負の整数で入力する |
| 分類 | 入力 |

状態:

| 状態 | 説明 | きっかけ |
| :--- | :--- | :--- |
| 通常 | 入力できる | 画面を開く |
| フォーカス | 枠が太くなり、キーボードの位置を示す | Tab、クリック |
| 入力済み・保存済み | 「入力: 保存済み」を横に示す | 入力の保存が成功 |
| 保存中 | 「保存しています」を横に示す | 入力の送信中 |
| 誤り | 欄の下に理由を文章で示す。アイコンを併記する | 小数、負数、空欄、文字 |
| 無効 | 押せない。理由を示す | 一時停止中、終了後、確定済みの週 |

入力:

| 入力 | 型 | 必須 | 既定 | 説明 |
| :--- | :--- | :--- | :--- | :--- |
| 値 | 非負の整数 | はい | 前回の入力、なければ空 | 発注数または生産要請数 |
| ラベル | 文字列 | はい | 「発注数」（工場は「生産要請数」） | 欄の上に常に表示する |

画面の幅: デスクトップ（1024px 以上）だけを対象にする。

アクセシビリティ:

| 要件 | 実装 |
| :--- | :--- |
| 役割 | 数値の入力（ネイティブの入力欄） |
| キーボード | Tab で移動。Enter で「確定する」ボタンへ移らず、保存は自動 |
| ラベル | 欄の上に常に見えるラベル。プレースホルダーだけに頼らない |
| コントラスト | 文字は 4.5:1 以上、枠は 3:1 以上 |
| スクリーンリーダー | 誤りは欄に関連づけて読み上げる。保存の状態は控えめな更新領域で知らせる |
| フォーカス | 誤りがあるとき、最初の誤りの欄にフォーカスを移す |

### 12 ステップの進み具合の表示

| 項目 | 値 |
| :--- | :--- |
| 部品 | ステップの進み具合 |
| 説明 | 現在週と 12 ステップのどこにいるかを示す |
| 分類 | 表示 |

- 完了、現在、これからを、色だけでなく、記号（印）と文字で区別する
- 参加者の入力が要るステップ（⑪）は「入力中」と示す。システムのステップは自動で進む
- アクセシビリティ: 現在のステップを `aria-current` で示し、進み具合を文章でも読めるようにする

### 他の役割の入力状況

| 項目 | 値 |
| :--- | :--- |
| 部品 | 入力状況の表示 |
| 説明 | 「4 役割のうち N が入力済み」だけを示す（参加者）。進行役は役割別に示す |
| 分類 | 表示 |

- 参加者の画面では、どの役割かを示さない（Q4）
- 更新があったら、控えめな更新領域で読み上げる

### 確認ダイアログ

| 項目 | 値 |
| :--- | :--- |
| 部品 | 確認ダイアログ |
| 説明 | 取り消せない操作（週の確定、ゲームの終了、担当者の入れ替え）の前に、何が起きるかを示して確認する |
| 分類 | フィードバック |

- 文面に、操作の名前、対象（第 5 週など）、結果（「確定後は変更できません」）を書く
- ボタンは「実行する」と「やめる」。初期のフォーカスは「やめる」
- キーボード: Escape で閉じる。フォーカスをダイアログの中に留め、閉じたら呼び出した要素に戻す
- 取り消せる操作（入力の変更、一時停止、再開）には、確認を出さない（Q5）

### 結果の比較

| 項目 | 値 |
| :--- | :--- |
| 部品 | 比較表示（グラフと表） |
| 説明 | 指標（注文、在庫、受注残、出荷、費用）を選び、需要と 4 役割の時系列を比較する |
| 分類 | 表示 |

- 「グラフ」と「表」を切り替えられる。同じ数値を示す（Q6）
- グラフは、線種（実線、破線、点線、一点鎖線）と印（丸、バツ、プラス、星）で系列を区別する。色だけに頼らない
- データ点にキーボードで移動でき、値を読み上げる。表では、行と列の見出しを関連づける
- 50 週の多い点でも、読み取れる大きさを保つ

### 役割の割当て

| 項目 | 値 |
| :--- | :--- |
| 部品 | 役割の割当て |
| 説明 | 参加者を役割に割り当てる。準備中は自由、進行中と一時停止中は同じ役割の担当者の入れ替えだけ |
| 分類 | 入力 |

- 1 つの役割の定員は 4 人。超える割当てはできない理由を文章で示す
- 選択肢は、状態によって変わる（進行中は他の役割を出さない）
- キーボード: 矢印キーで選択肢を移動し、Enter で選ぶ

## 誤りの文言の方針

- 何が起きたか、なぜか、次に何をするかを、日本語の文章で書く。内部のコードやスタックトレースは出さない
- 例:
  - 週数が範囲外: 「週数は 1〜50 で入力してください」
  - 参加コードが無効: 「この参加コードは見つかりません。コードを確かめてください」
  - 進行中: 「このゲームは進行中のため、新しく参加できません。進行役に連絡してください」
  - 確定不可: 「一次卸の入力がまだです。入力がそろうと確定できます」

## 通信と更新

- 状況の更新は、画面の再読み込みなしで反映する（反映の方式は、設計の工程で決める）。反映までの待ち時間の目標は NFR3 に従う（仮の値）
- 通信が切れたら、帯で知らせる。復帰したら、保存済みの内容を示す
