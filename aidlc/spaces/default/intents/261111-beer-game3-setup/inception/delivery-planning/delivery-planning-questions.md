# Delivery Planning 質問

6 つの Unit を、どの順で、どの大きさで作るかを決めるための確認です。ここでいう Bolt は、作る作業の一部分を 1 回通して、動くものを残す単位です（1 つ以上の Unit を受け持ちます）。薄い一通り（ウォーキングスケルトン）は、最初に作る、全体を端から端まで通す最小の動くものです。Unit の依存の形は決まっているので（`unit-of-work-dependency.md`）、ここで決めるのは、その形が許す順序の中の選び方です。

## Q1. [デリバリー] 何を先に作るか

U1（薄い一通り）の後に、U2〜U6 をどの考え方で並べますか？ U1 を最初に作ることは、team の方針で決まっています。U2、U3、U4 は U1 だけに依存し、互いに依存しません。

A. リスク優先。U1 の後に、失敗したときの影響が大きい U2（週確定の保証、再現性）と U4（権限、復元）を先に作り、運営操作と結果を後にする
B. 価値優先。U1 の後に、授業で最初に使う場面に近い U3（運営操作）と U5（結果）を先に作り、U2 と U4 を後にする
C. 混ぜる。U1 の後に U2、次に U3 と U4、次に U5、最後に U6

## Q6. [アーキテクト] 前の工程のレビューの気になる点を、どこで直すか

Units Generation と Contract Design のレビューで、いくつかの気になる点が出ました。どちらも承認済みで、計画に影響するのは、U1 が持つ範囲です。主な点は次のとおりです。

- 参加者を特定する token の最小の形を、U1 に含める必要がある（他役割の情報の拒否に必要）
- 観察者用コードの発行を、作成を実装する U1 に含めるのが、決定済みの方針（ADR-005）に沿う
- AccessCode、U1 の token、冪等性の記録の保存先の表が、どの Unit にも割り当てられていない

A. 次の Functional Design で U1 の範囲を直す。この計画は、U1 がこれらを含む前提で組む
