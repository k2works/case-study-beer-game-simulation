# 外部の待ちの一覧（External Dependency Map）

チームの外の事情で、作業が止まりそうなものを、どの Bolt（作る作業の一部分を 1 回通して、動くものを残す単位）が使うかと合わせて並べます。ほかは AI が自分で完結するため、外部の API やほかのチームの引き渡しはありません。

## 一覧

| # | 待ち | 持ち主 | 待ち時間 | 止める Bolt | 遅れたときの対処 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| E1 | JSD の既定の需要系列の確定（`requirements.md` の ASM-01 の具体的な値） | 人（プロダクトの判断） | 不明 | B2（キット準拠の判定の受入） | 「カスタム」で進める。キット準拠の判定は、試験用の系列と設定で検証し、JSD 準拠の受入判定は保留する（FR1.7） |
| E2 | 初期パイプライン数量 4 の、キットの盤面との照合 | 人（プロダクトの判断） | 不明 | B1（初期状態）、B2 | 4 を仮の値として進める。照合後に、設定の既定を直す |
| E3 | beer-game3 専用の AWS 環境の用意 | 人（運用） | 不明 | B1（staging の自動デプロイの土台） | 自動デプロイだけを後ろにずらす。CI（formatter、linter、type-check、テスト）は、AWS なしで先に動かす |

## 補足

- E1 と E2 は、Functional Design の完了までに確定する予定です（`requirements.md` の未確定事項）。
- E3 の対処は、`delivery-planning-questions.md` の Q4 の A に従います。遅れても、薄い一通りの動作の確認（ローカルと CI）は止めません。
- 次の項目は、外部の待ちではなく、仮の測定値の確定です。NFR 要件の工程で扱います: 応答性、可用性、セキュリティ、プライバシー、アクセシビリティ、可搬性（`requirements.md` の NFR3、NFR5〜NFR8、NFR10）。
