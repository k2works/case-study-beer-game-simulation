# 観測性の要件 - U3 u3-facilitation

U3（運営操作）の観測性と監査の要件です。元の要件は `requirements.md` の NFR9（監査性）と、U1 から引き継ぐ構造化ログです。構造化ログとヘルスチェックの範囲は、U1 の `observability-requirements.md`（最小）を引き継ぎます。U1 の構造化ログは監査の証跡ではなく、U3 が作る操作の履歴が監査の証跡です。

出典: `requirements.md`（NFR9）、`rules.md`（BR13.1〜BR13.6）、`entities.md`（OperationLogEntry）、`functional-spec.md`（履歴の種類）、`nfr-requirements-questions.md`（Q2 拒否は構造化ログ）。

## 要件

| ID | 要件 | 確かめ方 |
| :--- | :--- | :--- |
| NFR9.1 | 設定、役割変更、代理入力、週確定、一時停止、再開、終了の 7 種類の操作それぞれに、誰が、いつ、何をしたかを履歴に残す。操作と同じ保存の中で書き、履歴を残せなければ操作も失敗させる | 7 種類それぞれの操作を行ったゲームで、履歴を取得して、7 種類すべてが残っていることの試験（AC5.6.1、BR13.1） |
| NFR9.2 | 履歴は追記だけで、更新も削除もしない。順序はゲーム内の連番（sequence）で決まり、取得は昇順で返す。アプリケーションは履歴の行を更新する処理を持たない | 履歴の更新と削除の処理が存在しないことの確認。連番が欠けず重複しないことの試験（BR13.2） |
| NFR9.3 | 履歴の取得は進行役だけができる。履歴には資格情報の平文（コード、token）を含めない。時刻は、注入した時計から得る | 参加者が履歴を要求して拒否される試験。履歴の内容に資格情報の文字列が無いことの試験（BR13.5、BR13.6） |

拒否された進行役の操作（403、409）を構造化ログに残す要件は、セキュリティの要件 NFR6.6 に一本化している（観測性側では定義しない）。

## ログと履歴の使い分け

| | 構造化ログ（U1 から引き継ぎ） | 操作の履歴（U3 が作る） |
| :--- | :--- | :--- |
| 目的 | 障害の調査、応答時間の測定 | 誰が何をしたかの監査、授業の振り返り |
| 残す操作 | すべての要求（成功と拒否） | 成功した 7 種類の操作 |
| 保存先 | ログの出力 | PostgreSQL（ゲームの集約の一部） |
| 保持 | 運用で決める（Operation） | ゲームと同じ期間。ゲームの削除と同時に消える |
| 進行役への表示 | しない | 履歴の取得で見られる |

## 引き継ぐもの

- 要求ごとの識別子、構造化ログの形式、ヘルスチェック（U1 の要件。U1 の NFR3.5 は要求の識別子とログの形式、NFR3.6 はヘルスチェック、NFR6.4 は資格情報を出さないこと）はそのまま使う。U3 は、これらの番号を別の意味で使わない。
- 指標、アラートのしきい値、SLO、ダッシュボードは、後の Operation で定める。U3 は、一時停止の長さや操作の回数の指標を新しく作らない。
