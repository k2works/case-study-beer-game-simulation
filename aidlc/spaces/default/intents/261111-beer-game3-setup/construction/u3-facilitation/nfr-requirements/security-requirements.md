# セキュリティの要件 - U3 u3-facilitation

U3（運営操作）のセキュリティの要件です。元の要件は `requirements.md` の NFR6 と NFR7 です。U3 の操作は、ゲームを止める、終わらせる、担当者を替える、他人の代わりに入力するという強い権限を持つため、進行役用コードの判定と、資格情報の扱いが中心です。コードと token の発行、鍵付きハッシュ、暗号化、CSP などの共通の要件は、U1 の `security-requirements.md` を引き継ぎます。

出典: `requirements.md`（NFR6、NFR7）、`functional-spec.md`、`rules.md`（BR9.8、BR10.2〜BR10.4、BR10.6、BR11.1〜BR11.4、BR12.2、BR13.5、BR13.6、BR14.2、BR14.3）、`entities.md`、`contract-summary.md`（C1、C4）、`nfr-requirements-questions.md`（Q2 拒否の記録）。

## 認可の前提

- 進行役の操作は、進行役用コードを持つ人だけができる。参加コード、参加者の token、観察者用コードでは、どの進行役の操作もできない（BR9.8）。
- 終了は reason ごとに認可が違う。進行役の終了（facilitator）だけが進行役用コードを要る。最終週の確定による終了（finalWeek）と、放置による自動終了（autoEnd、U5）は内部の呼び出しで、外部の要求としては受け付けない。
- 権限の判定は、毎回の要求で、サーバー側で行う。画面で隠すだけにしない。

## 要件

| ID | 要件 | 確かめ方 |
| :--- | :--- | :--- |
| NFR6.1 | 一時停止、再開、終了、担当者の入れ替え、代理入力、進行管理の取得、履歴の取得は、進行役用コードの判定を通す。参加者の token、参加コード、観察者用コード、無資格の要求は 403 `forbidden` で拒否し、状態を変えず、進行役の投影の項目も応答に含めない。終了の reason が finalWeek と autoEnd は、外部の要求の入口を持たない | 各操作を参加者の token、観察者用コード、無資格で呼ぶ自動試験（AC2.8.2、BR9.8、BR14.3、BR13.5）。reason を外部から指定できないことの試験 |
| NFR6.2 | 入れ替えで発行する復帰用 token の平文は、その応答でだけ返す。応答は `Cache-Control: no-store` を付け、ログ、履歴、冪等性の記録、エラーの応答に平文を残さない。保存するのはハッシュだけ。画面は、表示した token を再表示せず、閉じたら保持しない | 応答ヘッダの検査。ログ・履歴・DB を調べて平文が無いことの自動試験（BR10.2、BR13.6） |
| NFR6.3 | 入れ替えると、旧担当者の token は失効し、以後の旧 token での要求を 403 で拒否する。失効は入れ替えと同じ保存の中で行い、新しい token の発行だけが残る状態を作らない。有効期間と試行回数の制限は U4 が足す | 入れ替え直後の旧 token の拒否の試験（AC2.6.1、BR10.4）。保存の失敗を注入して、旧 token が有効のまま、新しい担当者もできないことの試験 |
| NFR6.4 | 進行管理の投影は、入力済みの値そのものを含めない。代理入力の値は、履歴にだけ残る。参加者の応答には、自分の役割の入力者のラベルだけを含め、他の役割の担当者の情報は含めない | 進行管理と参加者の投影の自動試験（BR14.2、BR12.2、U1 の BR4.1） |
| NFR6.5 | 入れ替えの表示名は、サーバー側で 1〜40 文字を検証し、画面に出すときは出力の時点でエスケープする。履歴、ロビー、進行管理、共同担当の通知に出すラベルも同じ。履歴の取得の入力（なし）、入れ替えの旧担当者の識別子と役割は、型と列挙値を検証する | 表示名に `<script>` を含む入れ替えの試験。不正な識別子と役割の拒否の試験（BR10.2、BR12.4） |
| NFR6.6 | 拒否された進行役の操作（403、409）は、構造化ログに残す。ログには種類、操作、理由、要求の識別子、ゲームの識別子を出し、コード、token、鍵は出さない。履歴（OperationLogEntry）には残さない | ログの出力の自動試験（拒否の行が出ること、資格情報の文字列が出ないこと）。履歴に拒否が残らないことの試験 |
| NFR6.7 | 成功した要求を含む、すべての要求の構造化ログで、認可ヘッダ、リクエストの本文、レスポンスの本文を出力しない。入れ替えの成功時のログにも、平文の token が出ない | 入れ替えを成功させた後のログの出力に、発行した token の文字列と進行役用コードが無いことの自動試験（NFR6.2 の試験に含める） |
| NFR7.1 | 履歴は、表示名以外の個人情報を持たない。参加者のラベル（表示名と参加順）と識別子だけを持つ。ゲームの保持期間と同じ期間だけ保持し、ゲームの削除（U5）と同時に消える。実装の削除は U5 | 履歴の項目の確認。削除の試験は U5 |

## 脅威の考慮

| 脅威 | 対処 |
| :--- | :--- |
| 参加者による進行役の操作（一時停止、終了、代理入力） | NFR6.1。進行役用コードがなければ拒否する |
| 進行役用コードの盗用 | 128 ビット以上の乱数、ハッシュだけを保存する（U1 の NFR6.3）。再表示も再発行もしない。盗用されても、履歴に操作が残るため、後から追える |
| 入れ替えで発行した token の漏えい | NFR6.2。平文は一度だけ。紛失したらもう一度入れ替える |
| 旧担当者が入れ替え後も操作する | NFR6.3。旧 token は即座に失効する |
| 進行管理から他の参加者の入力値を知る | NFR6.4。入力値を投影に含めない |
| 代理入力や履歴の改ざん | 履歴は追記だけで、更新も削除もしない（`observability-requirements.md` の NFR9.2） |
| 表示名によるスクリプトの注入 | NFR6.5。U1 の NFR6.9、NFR6.10（CSP）と併せて防ぐ |
| ログからの漏えい | NFR6.6、NFR6.2 |

## コンプライアンス

個人情報は表示名のみで、履歴にも同じ範囲に限る（NFR7.1）。保持期間と削除は U5 が足す。
