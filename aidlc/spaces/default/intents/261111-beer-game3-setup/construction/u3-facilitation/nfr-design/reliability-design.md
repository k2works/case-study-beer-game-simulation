# 信頼性の設計 - U3 u3-facilitation

`reliability-requirements.md`（NFR1.1、NFR2.1〜NFR2.3、NFR5.1、NFR5.2）を満たす設計です。トランザクション、版の検査、障害の扱い、ヘルスチェックは、U1 の `reliability-design.md` を引き継ぎます。

## 設計

| 要件 | 解決 |
| :--- | :--- |
| NFR1.1 結果の不変 | 一時停止と再開は、`status` だけを変え、週の状態、遅延の枠、入力済みの値に触れない。入れ替えは、RoleAssignment と Participant と ReturnToken だけを変え、WeekRecord と PipelineSlot に触れない。代理入力は、通常の入力と同じ保存の関数を通り、入力した主体の項目だけが違う。週の計算（SimulationEngine）は、これらの操作を知らない |
| NFR2.1 操作と履歴の原子性 | 状態を変える操作は、ゲームの行を占有したトランザクションの中で、状態の更新と履歴の追記を行い、1 回でコミットする。履歴の追記だけを別の処理にしない。入れ替えは、ゲームの行の占有の直後に、次の事前検査を占有の中で行う: ゲームの状態が進行中か一時停止中であること（合わなければ 409 `state`）、旧担当者がいまその役割に割り当てられていて `replaced_at` が null であること（合わなければ 409 `conflict`）、表示名の検証。検査を占有の外に置かないため、同じ旧担当者への二重の要求で、新しい参加者が 2 人作られない（BR10.6）。検査に通ったら、次を 1 つのトランザクションに入れる: 旧 RoleAssignment の削除、新しい Participant と RoleAssignment の作成、旧 token の失効、新しい token の保存、旧 Participant の `replaced_at`、履歴の追記、`next_log_sequence` の更新、ゲームの版の更新 |
| NFR2.2 終了の原子性 | 最終週の確定は、U1 の確定のトランザクションの中で、終了への遷移、`end_reason`、終了の履歴を行う。確定の途中で失敗したら、ロールバックして、終了にも履歴にもならない。進行役の終了と最終週の確定は、同じ行の占有で順に処理する |
| NFR2.3 状態の検査 | 占有の中で、遷移の表（一時停止は進行中から、再開は一時停止から、終了は進行中か一時停止から。終了済みへの終了は冪等）を検査する。表に合わない操作は 409 `state`。識別子の照合は状態の検査より先（U1 の判定の順）で、以前に成功した識別子の再送は前回の結果を返す。参加者の入力では、占有の中で、入力者が現在その役割に割り当てられていることと token が失効していないことも再検査する（`security-design.md` の NFR6.3）。入れ替えの事前検査は NFR2.1 に書く |
| NFR5.1 状態の保持 | `status` と `end_reason` は games の行に保存する。再起動後も、一時停止と終了の状態から続けられる。入力は入力した時点で保存する（U1） |
| NFR5.2 失効と復帰 | 入れ替えで旧 token を失効させる設計は NFR2.1 に含む。有効期間と復帰は U4 が足す。U3 は token の表に `revoked_at`（U1）を使い、列を足さない |

## 障害の扱い

| 障害 | 設計 |
| :--- | :--- |
| 操作と履歴の保存の失敗 | ロールバック。500 `internal`。状態は操作の前のまま。画面が取り直して確かめる |
| 入れ替えの応答の喪失 | 平文の token は再表示しない。進行管理の担当者一覧に新しい担当者が出ていれば、その担当者を旧担当者として、もう一度入れ替える。参加者が余分に作られ、参加順の番号が飛ぶことを許容する |
| 順番待ちの時間切れ | 3 秒で `unavailable`（503）。サーバーは自動で再試行しない |
| 終了の再送 | 冪等。現在の状態を返し、履歴を足さない |

## 移行

- `games.end_reason` を足し、既存の `ended` の行に `finalWeek` を補う（U3 の前に ended になる経路は最終週の確定だけ）。`games.next_log_sequence` を足し、初期値を 1 にする。
- 移行は、既存の列を削除も意味の変更もしない追加だけ。ロールバックの手順は、追加した列と表を落とす逆の移行として用意する。
