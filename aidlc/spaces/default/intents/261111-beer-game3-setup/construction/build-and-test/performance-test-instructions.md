# 性能試験の手順 - beer-game3

測定は U6 の負荷試験のスクリプトで行う（`apps/beer-game3/verification/load/`）。アプリケーションの内部を import せず、HTTP の公開の面だけを使う。

## 負荷の定義

| 区分 | 画面の数 | 内訳 |
| :--- | :--- | :--- |
| 通常負荷 | 75 台 | 15 チーム × 5（4 役割 + 進行役）。1 秒おきに取り直し、各チームが 1 分に 1 週を確定 |
| 最大想定 | 270 台 | 15 チーム × 18（同じ役割 4 人ずつ 16 + 進行役 + 観察者）。確定の頻度は通常負荷と同じ |

## 実行

| 試験 | コマンド | 時間 | 合否に使う指標 |
| :--- | :--- | :--- | :--- |
| 短い試験 | `DATABASE_URL=... npm --prefix apps/beer-game3 run verify:load:smoke` | 約 1 分 | 取り直し（通常負荷）の 95 パーセンタイル 500 ミリ秒以内、サーバーの異常・タイムアウト・接続失敗・想定外の応答 0 件、整合性の崩れ 0 件。入力の確定と反映は記録のみ |
| 本試験 | `DATABASE_URL=... npm --prefix apps/beer-game3 run verify:load:main` | 約 14 分（通常負荷 10 分 + 最大想定 3 分） | 上に加えて、入力の確定 1 秒、反映（仮想の利用者と実ブラウザ 1 チーム）2 秒、最大想定の取り直し 1 秒（いずれも 95 パーセンタイル） |
| 実ブラウザの反映の確認 | `npm --prefix apps/beer-game3 run verify:render` | 数十秒 | 5 画面 × 週の反映が 2 秒以内 |

## 結果の読み方

要約の JSON（`verdict.result`: `pass`、`fail`、`invalid`）。終了コードは 0、1、2。`invalid`（測定器の飽和など）は失敗として扱い、アプリケーションの不合格とは分けて報告する。実行環境（CPU、メモリ、Node.js と PostgreSQL の版）が要約に記録される。閾値は緩めず、超過したら環境の記録と同じコミットの繰り返しで原因を切り分ける。再実行で通ったことを合格にしない。

## CI での実行

`beer-game3.yml` の `load-smoke`（PR ごと）と `load-main`（`main` への PR、夜間、手動）。夜間と手動は、ワークフローが `main` に入るまで動かない。
