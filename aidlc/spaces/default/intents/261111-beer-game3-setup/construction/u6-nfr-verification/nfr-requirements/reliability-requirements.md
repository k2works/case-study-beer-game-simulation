# 信頼性の要件 - U6 u6-nfr-verification

U6 は新しい永続状態を足さないため、可用性や復旧の目標は持ちません（元の NFR5 は U4 が担当）。ここに書くのは、U6 の検証が「同じ入力から同じ判定が出る」「検証の後にデータが壊れていない」「試験が環境を汚さない」ことを保つための要件です。

出典: `requirements.md`（NFR1、NFR2、NFR5）、`unit-of-work.md`（U6）、`nfr-requirements-questions.md`（Q2、Q3）。

## 番号の付け方と、上流の NFR との対応

`NFRn.m` の詳細番号は、Unit ごとに 1 から振る（U1〜U5 と同じ慣例）。U6 の `NFR1.x`、`NFR2.x` は、上流の NFR1（再現性）と NFR2（整合性）の検証を、全体の負荷と CI で重ねて行う部分である。計算そのものの正しさ（golden test。u2-weekly-rules）と、週確定の原子性の作り（u1-walking-skeleton と u2-weekly-rules）は、各 Unit が担当する。

## 要件

| ID | 要件 | 確かめ方 |
| :--- | :--- | :--- |
| NFR1.1 | 既知系列の golden test（U2 が作る。50 週すべての在庫、受注残、注文、出荷、遅延、費用）は、プルリクエストごとの CI で毎回動かし、失敗したら統合させない。U6 は、この試験を CI の必須の工程に含める（Q7 の A） | CI の定義に、golden test を含む試験の工程があること。失敗すると CI 全体が失敗すること |
| NFR1.2 | 負荷試験の各チームの意思決定系列は、種付きの乱数で決める。同じ種と設定からは、同じ要求の列が作られる。実行の間隔や応答の時間は変わるが、送る内容は再現できる | 同じ種で 2 回作った要求の列が一致する試験 |
| NFR2.1 | 負荷試験の後、すべてのゲームで次を検査する。確定済みの週が欠けず連続している。同じ週が二重に確定されていない。入力の確定の応答で成功を返した値が、保存されている。1 件でも崩れていれば、負荷試験は失敗とする。**検査の入口**: 負荷をかけるのは HTTP の公開の面だけで行い、この整合性の検査だけは、試験用のデータベースへの読み取り専用の接続（SELECT だけ）で行う。応答の投影は役割ごとに見える範囲が違い、全ゲームの全週を確かめられないためである。検査はテーブルの構造に依存するため、移行で構造が変わったら検査も更新する | 負荷試験の終了時の整合性の検査（NFR9.1 の要約に結果を含める）。検査の接続が読み取り専用であること（書き込みを試みると失敗する） |
| NFR2.2 | 試験は環境を汚さない。負荷試験と画面の試験が作ったデータベースとプロセスは、成功しても失敗しても、終了時に片付ける。次の実行は、前の実行の残りに影響されない。**起動と破棄の責任**: 負荷試験のスクリプト自身が、アプリケーションを子プロセスとして起動し、試験用のデータベースサーバーの中に使い捨てのデータベースを作り、終了時（成功、失敗、中断のいずれでも）にアプリケーションを止めてデータベースを削除する。CI のワークフローは、PostgreSQL 18 のサービスコンテナを用意するだけで、データベースの中身には関与しない。画面の試験も、同じ方法でアプリケーションと使い捨てのデータベースを起動する | 失敗を注入した実行のあとで、残ったプロセスとデータベースがないことの検査 |
| NFR2.3 | 画面の試験は、固定の待ち時間（sleep）に頼らず、表示の状態の変化を待つ。時刻に依存する振る舞いは、時刻を注入して試験する。再実行で通る不安定な試験を、成功として扱わない | 試験の規約の検査（固定の待ちの使用がないこと）。CI で失敗した試験は、再実行でなく原因を直す |
| NFR5.1 | 参加者の切断からの復帰と、復帰用 token の有効期間の検証は U4 が担当する。U6 は、本試験の通常の動作の中で、接続の切れた画面が再び取り直しを始めた場合に、確定済みのデータを失わないことだけを、負荷試験の整合性の検査（NFR2.1）に含める | NFR2.1 の検査 |

## 根拠と設計への影響

- 負荷試験は、応答時間だけでなく、負荷の下でのデータの正しさも確かめる。応答が速くても、週が二重に確定したり欠けたりしていれば、授業の教材として信頼できない（元の NFR1、NFR2）。
- 乱数に種を持たせるのは、失敗した負荷試験を、同じ内容で再現して調べるためである。
- 試験の不安定さ（flaky）を許すと、閾値の超過が環境の揺れなのか劣化なのかが判断できなくなる。再実行で通すことを合格にしない（NFR2.3）。
