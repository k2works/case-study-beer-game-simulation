# セキュリティの要件 - U6 u6-nfr-verification

U6 は、新しい認証や認可の機能を足しません。U6 が作るもの（負荷試験のスクリプト、画面とアクセシビリティの試験、CI のワークフロー）が、守るべき情報や環境を傷つけないための要件です。ゲーム・役割単位の操作権限の検証（元の NFR6）は U1 と U4 が作り、U6 の負荷試験は、その検証が通る状態で動かします。

出典: `requirements.md`（NFR6、NFR7）、`unit-of-work.md`（U6）、`contract-summary.md`（C1 の認可）、`nfr-requirements-questions.md`（Q2 負荷試験の道具、Q7 CI の作成範囲）。

## 番号の付け方と、上流の NFR との対応

`NFRn.m` の詳細番号は、Unit ごとに 1 から振る（U1〜U5 と同じ慣例）。U6 の `NFR6.x`、`NFR7.x` は、上流の NFR6（コードの強度と権限の検証）や NFR7（保持と削除）そのものではなく、U6 が作る試験と CI を安全に動かすための要件である。上流の部分は、次の Unit が担当する。

| 上流の NFR | U6 が扱う部分 | U6 が扱わない部分（担当） |
| :--- | :--- | :--- |
| NFR6 セキュリティ | 試験と CI を、守るべき環境と情報から隔てる（本ファイルの NFR6.x） | 参加コードなどの強度、ゲーム・役割単位の権限の検証、試行回数の制限（u1-walking-skeleton と u4-access-recovery） |
| NFR7 プライバシー | 試験のデータと成果物に個人情報を持ち込まない（本ファイルの NFR7.x） | 保持期間、自動終了、削除（u5-results-retention） |

## 要件

| ID | 要件 | 確かめ方 |
| :--- | :--- | :--- |
| NFR6.1 | 負荷試験と画面の試験は、その試験のために起動した試験用のアプリケーションと試験用のデータベースにだけ向ける。本番と staging の接続先を既定にしない。接続先は環境変数で明示し、`localhost` 以外を指す場合は、明示の許可の設定がなければ実行を拒否する。許可して `localhost` 以外を指した場合は、失敗時の成果物（トレースと画面の画像。NFR7.2）を保存しない | 接続先の検査の試験。許可の設定がないまま `localhost` 以外を指すと、実行前に失敗すること。許可した実行で、成果物の保存が無効になること |
| NFR6.2 | CI のワークフローは、最小の権限で動かす。`contents: read` を既定にし、書き込みや OIDC の権限は、必要なジョブにだけ与える。U6 の CI は、シークレットを使わない（試験用のデータベースの接続は、使い捨てのコンテナの値である）。デプロイは含めない（Q7 の A） | ワークフローの定義を読む検査。デプロイ用の権限と環境が含まれないこと |
| NFR6.3 | 試験のデータは架空にする。表示名、参加コード、進行役用コード、復帰用 token は、試験の中で生成した値で、実在の個人を指さない。試験の資格情報は、使い捨てのデータベースの中でだけ有効である（NFR2.2 で、試験の終了時にデータベースとプロセスを破棄する）。これらの値を、試験のスクリプトが書く出力（ログ、結果の要約）に書き出さない。画面に表示された資格情報が、失敗時の成果物（トレースと画面の画像）に写ることは避けられないため、成果物は対象から外し、NFR7.2 の保持の期限で扱う | 試験のスクリプトが書くログと結果の要約の検査。生成した資格情報の値が含まれないこと |
| NFR6.4 | 新しく導入する依存（Playwright、axe-core とその Playwright 用の連携）は、版を固定し、ロックファイルに記録する。導入の前に、版の配布元と既知の脆弱性を確かめる。導入は dev の依存だけで、本番の成果物（`dist/`、コンテナ）に含めない | `package.json` とロックファイルの検査。`npm audit` の結果の確認。本番の成果物に含まれないことの確認 |

## プライバシー（NFR7）

| ID | 要件 | 確かめ方 |
| :--- | :--- | :--- |
| NFR7.1 | 試験は個人情報を使わない。画面の試験の画像、トレース、動画に、実在の個人の情報が映らない | 試験のデータの定義の検査（NFR6.3 と合わせる） |
| NFR7.2 | 試験の成果物（失敗時の Playwright のトレースと画面の画像）は、失敗した場合にだけ保存し、保持は 7 日にする。トレースには、通信の内容と画面の表示が含まれ、試験で生成した資格情報が写る。資格情報を伏せる手段は採らない（標準の設定で確かめられていないため）。代わりに、次の 3 点で危険を抑える。(1) 写る資格情報は、NFR6.3 のとおり使い捨てのデータベースの中でだけ有効で、試験の終了時に破棄されるため、成果物が残っても使えない。(2) 保持を 7 日に限る。(3) 試験用のアプリケーション以外（`localhost` 以外）を指した実行では、成果物を保存しない（NFR6.1） | ワークフローの定義の検査。保持の日数の設定。`localhost` 以外を指した実行で、成果物の保存が無効になること |

## 根拠と設計への影響

- 負荷試験は、うっかり本番や staging に向けると、実際の授業を妨げる。接続先を試験用に限り、その他は明示の許可なしに拒否する（NFR6.1）。
- Playwright のトレースと画面の画像は、通信の内容と画面の表示を保存するため、参加コードや復帰用 token が写る。資格情報を伏せる確かな手段がないため、伏せることを要件にせず、資格情報が使い捨てで成果物の時点では無効になっていること、保持が短いこと、試験用以外の接続先では保存しないことで抑える（NFR6.3、NFR7.2）。
- 依存の追加は、外部ライブラリの導入にあたる。U1 の技術スタックの決定（Playwright と axe-core を候補とする）の範囲に収め、版は Code Generation の時点で公式情報で確かめて決める（`tech-stack-decisions.md`）。
