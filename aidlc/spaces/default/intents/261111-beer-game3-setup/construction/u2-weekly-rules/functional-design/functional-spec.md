# 機能仕様 - U2 u2-weekly-rules

U2（週次ルールの完成）の振る舞いの仕様です。U1 の機能を土台に、キット準拠の判定、確定の保証、再現性、設定値の上限を足します。実体は `entities.md`、規則は `rules.md` が正本です。

## 受け持つストーリー

| ストーリー | 題 | 主な規則 |
| :--- | :--- | :--- |
| US1.6 | 進行役がキット準拠とカスタムを区別して設定する | BR6.1〜BR6.5 |
| US2.4 | 週確定は途中で失敗しても部分更新を残さない | BR7.1〜BR7.4 |
| US5.2 | 同じ入力から常に同じ結果が再現される | BR8.3 |
| （U1 のレビュー指摘） | 設定値の上限 | BR8.1、BR8.2 |

## ワークフロー

### W6 ゲームの種別を決める（US1.6）

1. 進行役がゲームを作成する（U1 の W1）。キット準拠のプリセットを選ぶか、各項目を指定する。
2. 設定値の上限を検査する（BR8.1）。範囲外なら、項目と上限を案内して拒否する。
3. 設定を KitPreset と比べる（BR6.3）。KitPreset の需要系列が未提供の間は、必ず「カスタム」にする（BR6.2）。
4. 種別（キット準拠／カスタム）をゲームに保存する。以降は変わらない（BR6.4）。
5. 画面と出力に、種別を表示する。

### W7 週を確定する（強化）（US2.4）

U1 の W5 を次のように強める。

1. 同じゲームの確定は、直列に処理される（U1 の BR4.6）。同時に届いた確定は、1 件だけが処理され、後の件は前回の結果か状態の拒否を返す（BR7.1）。
2. 前の週の確定済みの記録を読む。欠けていれば、確定を行わず、失敗にする（BR7.4）。
3. 計算し、結果をまとめて 1 つの保存の単位で書く。途中で失敗したら全体を元に戻す（BR7.2）。
4. 入力の二重送信は、識別子で 1 件として扱う（BR7.3）。

### W8 再現性を確かめる（US5.2）

1. 既知の初期状態と意思決定系列を与え、50 週を計算する。
2. 全週・全役割の在庫、受注残、注文、出荷、遅延の枠、費用を、固定した期待値と比べる（BR8.3）。
3. 2 回実行して、両方が期待値と一致することを確かめる。

期待値は、実装とは別の計算（Q2 の A）で作り、ファイルに固定する。需要は週 1〜4 が 4、週 5 以降が 8。意思決定は、決まった規則（たとえば、各役割が受注の数を発注する）にする。

## 状態の遷移

U2 は、ゲームの状態遷移（準備中、進行中、終了）を変えない。変わるのは、作成のときに決まる種別だけ。

| 項目 | 値 | 決まる時点 |
| :--- | :--- | :--- |
| setupKind | kit または custom | 作成（以後は変わらない） |

## エラーと端の場合

| 場面 | 振る舞い | 規則 |
| :--- | :--- | :--- |
| 初期在庫に 9999 超 | 422 validation。項目と上限を案内。他の入力は残る | BR8.1 |
| 在庫単価に 10000 超 | 422 validation | BR8.1 |
| 需要系列に 9999 超の値 | 422 validation | BR8.1 |
| 同時に 2 件の確定 | 1 件だけが確定。後の件は前回の結果か 409 state | BR7.1 |
| 確定の途中の保存失敗 | 500 internal。確定前の状態のまま | BR7.2 |
| 前週の記録が欠けている | 500 internal。状態は変わらない | BR7.4 |
| 週数を 30 週に変えたゲーム | 「カスタム」 | BR6.3 |
| JSD の系列が未提供のとき、キット準拠を指定 | 「カスタム」 | BR6.2 |

## この Unit の外で決まること

- 種別を含む出力（CSV、JSON）の実装は U5。U2 は、種別が作成時に決まることを保証する。
- 試験用に、プリセットの全項目と一致する設定を与える判定の試験（AC1.6.3）は、試験用の仮の系列を含むプリセットで行う。実際の KitPreset は未提供のまま。
- JSD の既定の需要系列と初期パイプライン数量 4 の照合は、人が決める（`external-dependency-map.md` の E1、E2）。
