# 性能の要件 - U5 u5-results-retention

U5（結果と出力、保持と削除）の応答性の目標です。元の要件は `requirements.md` の NFR3 です。負荷の前提（通常負荷 75 台、最大想定 270 台）と、取り直しの周期 1 秒は、U1 の `performance-requirements.md` を引き継ぎます。U5 は、終了後に開かれる結果と出力の要求、定期的に動く自動終了と削除の処理について、目標を足します。負荷試験で測って確かめるのは U6 の仕事です。

出典: `requirements.md`（NFR3、NFR8）、`functional-spec.md`、`rules.md`（BR21.5、BR22.1〜BR22.4、BR23.4、BR26.3〜BR26.5）、`contract-summary.md`（C1、C5）、`nfr-requirements-questions.md`（Q1 結果と出力の目標、Q2 定期処理の影響の上限）。

## 画面（NFR8）

| ID | 要件 | 確かめ方 |
| :--- | :--- | :--- |
| NFR8.1 | 結果画面は、指標の切り替え、費用の週ごと・累積の切り替え、導線（結果を見る、出力）を、キーボードだけで操作できる。選択中の指標と切り替えの状態を色だけで示さない。系列は線種・印・凡例で区別し（BR22.2）、数値の表を併記する（BR22.4）ため、グラフが読めなくても表で同じ情報を得られる。通常の文字は背景とのコントラスト比 4.5:1 以上、グラフの線と印は背景に対して 3:1 以上（WCAG 2.2 AA）。全体の検査は u6-nfr-verification が行い、U5 の画面も同じ検査を通す | U5 の画面の試験（Playwright）で、キーボードだけで終了後のゲームの結果画面を開き、指標を切り替え、出力を開始できること、線種と印が役割ごとに異なることを確かめる |
| NFR8.2 | 結果画面の初期の表示は、確定済みの週が 50 週のゲームでも、結果の応答のあと 1 秒以内に描画する。描画は、グラフ（SVG）と表を合わせて 400 点前後（50 週 × 4 役割の 1 指標ぶん）に収まる | 画面の試験（Playwright）で、50 週のゲームの結果の描画時間を測って記録する |

## 画面と出力の言語（NFR11）

| ID | 要件 | 確かめ方 |
| :--- | :--- | :--- |
| NFR11.1 | U5 が作る画面の文言（結果画面、出力ボタン、注意書き、列名の説明）と、エラーの理由・直し方は、日本語で作る。画面の金額は通貨の形（$ と小数 2 桁）で示す | 結果画面と出力の導線の画面の試験で、文言が日本語であることを確かめる |
| NFR11.2 | 出力（CSV と JSON）の列名と項目名、役割の値（`factory`、`wholesaler1`、`wholesaler2`、`retailer`）は、読み戻すための識別子として英語のままにする。NFR11 の「出力」は、画面の文言とエラーの理由・直し方を指すと解釈する（Q6 の A）。その代わりに、列名の意味と単位、役割の値と日本語の役割名の対応を、出力ボタンの近くに日本語で常に表示する（BR23.9）。日本語の表示名は UTF-8（CSV は BOM 付き）で崩れない | 日本語の表示名を含むゲームの出力を、CSV と JSON で読み戻して元の値と一致する試験。出力ボタンの近くに列名の説明が表示される画面の試験 |

## 根拠と設計への影響

- 結果と出力は、終了後に利用者が開く要求で、毎秒呼ばれる取り直しと違って回数が少ない。読む行は最大 200 行で小さいため、目標は取り直しの 500 ミリ秒より緩め、出力の整形を含む 2 秒にした（Q1 の A）。
- 終了したゲームは書き込みを受けないため、結果と出力は行を占有せずに読める（BR21.5）。書き込みの順番待ちに入らないことが、取り直しの目標を守る前提である。
- 定期処理は、通常の要求と同じデータベースの接続を使う。1 ゲームごとに短い保存へ分けて（BR26.5）、行の占有を 1 秒以内に抑え、1 回の上限で処理の全体の長さを抑える。目標を守れないときの調整手段は、上限の設定値の引き下げである（Q2 の A）。
