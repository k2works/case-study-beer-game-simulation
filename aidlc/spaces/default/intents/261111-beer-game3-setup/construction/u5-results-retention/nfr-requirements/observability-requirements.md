# 観測性の要件 - U5 u5-results-retention

U5（結果と出力、保持と削除）の観測性の要件です。元の要件は `requirements.md` の NFR9（監査性）と、U1 から引き継ぐ構造化ログです。構造化ログとヘルスチェックの範囲は、U1 の `observability-requirements.md`（最小）を引き継ぎます。U5 で増えるのは、定期処理（自動終了と削除）の結果と、結果と出力の取得です。拒否の扱いは U4 の方針（構造化ログに残し、履歴には残さない）に従います。

出典: `requirements.md`（NFR9）、`rules.md`（BR24.6、BR25.3、BR26.2、BR26.4）、`entities.md`（RetentionRunResult）、`functional-spec.md`、`nfr-requirements-questions.md`（Q4 定期処理の警告）。

## 要件

| ID | 要件 | 確かめ方 |
| :--- | :--- | :--- |
| NFR9.1 | 定期処理の 1 回分の結果（RetentionRunResult）を、構造化ログに必ず出す。項目は、開始時刻、自動終了の数、削除の数、失敗の数、skipped（ロックを取れず何もしなかったか）、所要時間（ミリ秒）。ゲームごとの行は、自動終了と削除のそれぞれについて、ゲームの識別子、時刻、理由（`autoEnd` または `retentionExpired`）だけを出す。表示名、ゲーム名、コード、token を含めない（BR24.6、BR26.4） | 1 回の処理のあとに、結果の行が 1 行出ること、ゲームごとの行に許された項目だけがあることの試験 |
| NFR9.2 | 失敗の重大度を分ける。1 つのゲームの自動終了または削除の失敗は `warn`（ゲームの識別子と失敗の種類を出す）、処理の全体の失敗（データベースに接続できない、など）は `error` で出す。ロックを取れない（skipped）は `info` で出す。複数のインスタンスで動かすと、ロックを取れないインスタンスでは skipped が通常の動作として続くため、skipped は連続の判定に数えない。直近 3 回の処理が連続して失敗（ゲームの失敗があった、または全体の失敗）になったら、その事実を `error` で出す（連続の回数を数える状態は、アプリケーションのメモリに持つ。再起動で 0 に戻ってよい）。すべてのインスタンスで処理が一度も行われていないこと（全体の停止）の検知は、後の Operation に渡す。警告のしきい値の判断と通知の仕組みは、後の Operation に渡す | 失敗を注入して、重大度が上の規則どおりであることの試験。3 回連続の失敗で `error` が出る試験。skipped が 3 回続いても、連続の `error` が出ない試験 |
| NFR9.3 | 自動終了は、操作の履歴（OperationLogEntry）に `end`（理由 `autoEnd`、actorKind `system`）として残る（U3 の NFR9.1、BR25.3）。削除はゲームごと消えるため、操作の履歴には残らず、構造化ログにだけ残る（BR24.6）。結果と出力の取得は、操作の履歴に残さない（読み取りのため） | 自動終了のあとに履歴を取得して `end` の行があること、結果と出力の取得の前後で履歴の件数が変わらないことの試験 |
| NFR9.4 | 結果と出力の取得を、構造化ログに残す。項目は、種類（`results` または `export:csv` または `export:json`）、ゲームの識別子、結果の大きさ（行数またはバイト数）、所要時間。資格情報は出さない（U1 の NFR6.4）。拒否（403、409、422）は、U4 の方針どおり構造化ログに種類と理由だけを出す | 取得のログ行に許された項目だけがあることの試験。拒否のログ行に資格情報が含まれないことの試験 |
| NFR9.5 | U5 では警告（アラート）の仕組みを設けない（Q4 の A）。メトリクスは、U1 の最小の範囲（要求ごとのカウンタ）を超えて新しく作らない。定期処理の遅れや失敗の増加を知らせる警告は、後の Operation で足す。その材料として、NFR9.1 と NFR9.2 のログを使えるようにしておく | 警告の定義が U5 の成果物に無いことの確認 |

## ログと履歴の使い分け（U5 の範囲）

| | 構造化ログ（U1 から引き継ぎ） | 操作の履歴（U3） |
| :--- | :--- | :--- |
| U5 の対象 | 定期処理の結果、削除、自動終了（ゲームごとの行）、結果と出力の取得、拒否 | 自動終了の `end`（システムによる）のみ |
| 目的 | 障害の調査、定期処理の動作の確認、削除の証跡（個人情報なし） | 誰が何をしたかの監査 |

## 引き継ぐもの

- 要求ごとの識別子、構造化ログの形式、ヘルスチェック（U1 の NFR3.5、NFR3.6）、資格情報を出さないこと（U1 の NFR6.4）はそのまま使う。要件の番号（NFRx.y）は、inception の NFRx を細分したもので、Unit ごとに独立している。この文書群で U1 の要件を指すときは「U1 の」を付け、付けない番号は U5 自身の要件を指す。
- 指標の収集の基盤、アラートのしきい値、SLO、ダッシュボードは、後の Operation で定める。
