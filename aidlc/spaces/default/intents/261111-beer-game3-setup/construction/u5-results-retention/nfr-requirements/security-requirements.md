# セキュリティの要件 - U5 u5-results-retention

U5（結果と出力、保持と削除）のセキュリティとプライバシーの要件です。元の要件は `requirements.md` の NFR6、NFR7 です。資格情報の特定、ゲーム・役割単位の権限の検証、同じ 403 の本文は U1・U4 を、暗号化と鍵の扱いは U1 の `security-requirements.md` を引き継ぎます。U5 は、結果と出力の権限、出力に含めるものと含めないもの、削除による個人情報の扱い、定期処理が攻撃面を増やさないことが中心です。

出典: `requirements.md`（NFR6、NFR7）、`functional-spec.md`、`rules.md`（BR21.1〜BR21.4、BR23.1、BR23.3、BR23.8、BR24.1〜BR24.6、BR26.1、BR26.2）、`entities.md`、`contract-summary.md`（C1、C5）、`nfr-requirements-questions.md`（Q2 の前提、U1 の Q3）。

## 要件

| ID | 要件 | 確かめ方 |
| :--- | :--- | :--- |
| NFR6.1 | 結果の取得は、終了したゲームの参加者（有効な token）と進行役だけに許す。出力は進行役だけに許す。観察者、無効または期限切れまたは失効した token、無効なコード、別のゲームの資格情報、存在しない（削除済みを含む）ゲームは、U4 の無効な資格情報と同一の 403 の本文で拒否し、ゲームや役割の存在を応答の違いで明かさない。ゲームが終了していない間の結果は、権限のある人にも返さない（理由は「終了するまで見られない」）。終了前の出力の要求は、進行役に 409 `state` を返す（BR21.1、BR21.2、BR23.1） | 資格情報の種類（参加者、進行役、観察者、なし、無効、別のゲーム、存在しないゲーム）× ゲームの状態（準備中、進行中、一時停止、終了、削除済み）の組み合わせの網羅試験。観察者の結果の拒否の試験（AC4.1.4、AC5.4.1 の考え方） |
| NFR6.2 | 結果に、参加者の表示名、コード、token、ハッシュ、冪等の識別子を含めない。出力には、各週の入力者の表示名（`decidedByDisplayName`）を含めるが、コード、token、ハッシュ、冪等の識別子、操作の履歴は含めない（BR21.4、BR23.8）。表示名は、入れ替え済みの参加者のものも含め、その週の入力者のものだけである | 結果と出力のすべての項目を走査して、コードと token と鍵の値が含まれないことの試験。出力に表示名以外の個人情報が含まれないことの試験 |
| NFR6.3 | 出力は進行役だけが取得できる。ファイルは `Content-Disposition: attachment` と `Cache-Control: no-store` で返し、ファイル名にゲーム名や表示名を使わない。出力の CSV は、先頭が `=`、`+`、`-`、`@` の値も元のまま出す（Functional Design の Q6 の A。読み戻して元の値と一致することを優先する） | 出力の応答ヘッダの試験。先頭が `=` の値を含む出力が元の値のまま読み戻せる試験（BR23.3） |
| NFR6.8 | 表計算ソフトで式として実行される表示名（CSV インジェクション）への対策を、入口と出口の両方で行う（Q5 の A）。脅威は、表示名を自由に決められる参加者が `=HYPERLINK(...)` のような式を表示名にし、出力を表計算ソフトで開く進行役の側で実行されることである（表示名は 40 文字まで入るため、短い式は収まる）。「進行役だけが取得できる」ことは被害者を進行役に絞るだけで、リスクを下げない。(1) 入口: 参加（U1 の join）と担当者の入れ替え（U3 の replace）で、前後の空白を取り除いた表示名の先頭が `=`、`+`、`-`、`@`、タブ、復帰のものを 422 で拒否する（BR23.10）。すでに保存されている表示名は変えない。(2) 出口: 出力ボタン（CSV、JSON）の近くに、表計算ソフトで開くときの注意を必ず表示し、画面の試験で確かめる（BR23.9）。CSV の値は変えないため、読み戻しは元と一致する。この対策で残るリスク（対策の導入前に保存された表示名、先頭以外の位置の式、検証をすり抜ける文字）は、注意書きと進行役の操作に任せて受け入れる | 参加と入れ替えで、先頭が `=`、`+`、`-`、`@`、タブ、復帰の表示名が 422 になる試験（U1 と U3 の試験に足す）。出力ボタンと同時に注意が表示される画面の試験。先頭が空白のあとに `=` の表示名も拒否される試験 |
| NFR6.4 | 削除を含む定期処理のログに、ゲームの識別子、削除の時刻、理由、件数以外を出さない。表示名、ゲーム名、コード、token、鍵を含めない（U1 の NFR6.4）。結果と出力の取得のログにも、資格情報を出さない（BR24.6） | 削除と自動終了と取得のログ行に、表示名とコードの値が含まれないことの試験 |
| NFR6.5 | 定期処理に HTTP の入口を設けない。自動終了と削除を外から起動する経路、運営者だけが持つ秘密の値による管理用の入口を作らない。攻撃面を増やさず、起動はアプリケーションの内部のタイマーだけにする（BR26.1、Q9 の A） | ルーティングの一覧に、定期処理を起動する経路がないことの試験 |
| NFR6.6 | 設定値（保持期間、自動終了の期間、周期、1 回の上限）は、起動時に範囲を検査し、範囲の外、または整数でない値なら起動を拒否する（保持期間と自動終了の期間は 1 日以上に限り、0 を許さない）。範囲の検査は、範囲外の値を拒否するもので、範囲の中の入力ミス（たとえば 30 の入力ミスの 3）は防げない。意図せず多くのゲームを削除することへの守りは、次の 3 つで行う。(1) 起動時に、有効な設定値（保持期間、自動終了の期間、周期、1 回の上限）をログに 1 回出す。(2) 保持期間または自動終了の期間が既定（30 日）より短いときは、その旨を `warn` で出す。(3) 1 回の上限（既定 100 件）で周期ごとに分けて削除し、運用手順書に、保持期間を短くする前に出力を取得する案内を書く（Operation への引き渡し事項）（BR24.1、BR25.1、BR26.1） | 範囲の内外の値、0、負の値、小数、空文字で起動を試す試験。起動時のログに有効な設定値が出ること、既定より短い設定で `warn` が出ることの試験 |
| NFR6.7 | 削除の対象の判定は、サーバー側の時計と、データベースに保存された終了の時刻だけで行う。利用者の入力（要求の本文、ヘッダ）で、削除の対象や期限を変えられない。削除は、終了したゲームだけに行い、進行中のゲームを保持期間では削除しない（BR24.2、BR24.7） | 要求の入力で削除の判定が変わらないことの確認。進行中のゲームが保持期間では削除されない試験 |

## プライバシー（NFR7）

| ID | 要件 | 確かめ方 |
| :--- | :--- | :--- |
| NFR7.1 | 保持期限を過ぎたデータを削除する。保持期間の既定は終了後 30 日で、運営者がアプリケーションの設定で変更できる（全ゲーム共通）。放置されたゲームは、最後の操作から 30 日で自動終了し、その時点から保持期間を数える（NFR7）。判定はそのときの設定で毎回行い、設定を短くすると、すでに終了したゲームにも適用する（BR24.1、BR24.2、BR25.1） | 終了から 31 日たったゲームが既定で削除される試験（AC5.1.1）。保持期間を 7 日にした設定で、終了から 8 日たったゲームが削除される試験（AC5.1.2）。最後の操作から 30 日たった一時停止中のゲームが自動終了し、その時点から保持期間が数えられる試験（AC5.1.3） |
| NFR7.2 | 削除は、ゲームに紐づくすべてのデータ（表示名を持つ参加者、割当て、週の記録、各コード、復帰用 token、冪等の記録、操作の履歴）を対象にする。データベースに「削除済み」の痕跡（表）を残さない。削除後、参加コードは無効になり、そのゲームへの要求は存在しないゲームと同じ 403 で拒否される（BR24.3、BR24.4、BR24.6） | 削除後に、すべての表でゲームの識別子の行が 0 件であることの試験。削除後の参加の試行が無効なコードとして扱われる試験 |
| NFR7.3 | ログとバックアップに残る個人情報の扱いは、U5 では定めきれない。削除ログには表示名を出さない（NFR6.4）。構造化ログに残る接続元の保持期間（U4 の NFR7.1 で Operation に渡したもの）と、データベースのバックアップの保持期間は、ゲームの保持期間（既定 30 日）を超えないことを目標にして、後の Operation で定める。バックアップに削除前のデータが残る間は、削除は即時の消去ではなく、バックアップの保持期間の経過で完了する | Operation の工程で、ログとバックアップの保持期間を運用手順書に記載したことを確認する（U5 の成果物には、この目標を引き渡し事項として記録する） |

## 残るリスク

- 対策の導入前に保存された表示名や、先頭以外の位置にある式は、CSV を表計算ソフトで開くと実行されうる（NFR6.8）。出力ボタンの近くの注意書きと、進行役の操作（テキストとして読み込む）に任せて受け入れる。
- バックアップに削除前のデータが残る（NFR7.3）。Operation の工程で期間を定める。
- 設定で保持期間を大きく短くすると、多くのゲームが一度に削除対象になる。範囲の検査では防げないため、起動時の設定値のログと警告、1 回の上限で抑える。短くする前に運営者が出力を取得する案内が運用手順書に必要である（引き渡し事項）。

| 先 | 内容 |
