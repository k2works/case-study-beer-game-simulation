# 観測性の要件 - U1 u1-walking-skeleton

U1（薄い一通り）の観測性の要件です。Q4 の決定どおり、最小の範囲にします。本格的な監視、アラート、ダッシュボードは、後の Operation で定めます。

出典: `requirements.md`（NFR3、NFR6、NFR9）、`security-requirements.md`、`nfr-requirements-questions.md`（Q4 最小）。

## 要件

| ID | 要件 | 確かめ方 |
| :--- | :--- | :--- |
| NFR3.5 | すべての要求に、要求ごとの識別子を付け、構造化ログ（JSON）に出す。ログは、時刻、要求の識別子、操作、結果（成功と拒否の種類）、応答時間を持つ | ログの出力の自動試験。応答時間は、NFR3.1 と NFR3.3 の測定の元になる |
| NFR3.6 | ヘルスチェックの入口を持つ。アプリケーションが動いていることと、データベースに接続できることを返す | ヘルスチェックの自動試験 |
| NFR6.4 | ログとエラーの応答に、コード、token、暗号化の鍵、表示名以外の個人情報を出さない（`security-requirements.md`） | 資格情報の文字列が出ないことの自動試験 |

## ログの標準

- 形式: 1 行 1 件の JSON。
- 水準: エラー、警告、情報。拒否された要求（403、409、422）は情報、保存の失敗や想定外の例外はエラー。
- 内容: ゲームの識別子と役割は出してよい。コードと token は出さない。入力の数値は出してよい。
- 追跡: 要求の識別子で、1 つの要求のログをたどれる。

## この Unit の外で決まること

- 指標（エラー率、応答時間の分布）、アラートのしきい値、SLO、ダッシュボードは、後の Operation で定める（Q4 の A）。
- 設定、役割変更、代理入力、週確定、停止、再開、終了の操作の履歴（監査の証跡）は、U3 が作る（NFR9）。U1 の構造化ログは、監査の証跡ではない。
