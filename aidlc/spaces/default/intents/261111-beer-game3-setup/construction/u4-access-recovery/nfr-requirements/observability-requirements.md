# 観測性の要件 - U4 u4-access-recovery

U4（復帰と権限）の観測性の要件です。元の要件は `requirements.md` の NFR9（監査性）と、U1 から引き継ぐ構造化ログです。構造化ログとヘルスチェックの範囲は、U1 の `observability-requirements.md`（最小）を引き継ぎます。U4 で増える拒否は、無効な token、無効なコード、429 です。U1 と U3 の方針に従い、拒否は構造化ログに残し、操作の履歴（OperationLogEntry）には残しません。

出典: `requirements.md`（NFR9）、`rules.md`（BR17.3、BR18.1、BR18.2、BR19.1）、`functional-spec.md`、`nfr-requirements-questions.md`（Q4 拒否の記録と警告）。

## 要件

| ID | 要件 | 確かめ方 |
| :--- | :--- | :--- |
| NFR9.1 | U4 で増える拒否（無効な token、無効なコード、レート制限）を、構造化ログに残す。ログには種類、接続元、ゲームの識別子（特定できるとき）、要求の識別子を出す。資格情報（コード、token、鍵）は出さない（U1 の NFR6.4）。種類は 3 つで、`invalid_token` は `Authorization` ヘッダの資格情報（参加者の token、進行役用コード、観察者用コード）が無効なとき、`invalid_code` は参加コードによる参加の試行が無効なとき、`rate_limited` は 429 のときである。資格情報は有効だが権限のない要求の拒否（403 `forbidden`）は、既存の種類（結果の拒否の種類）で出す | 3 種類の拒否それぞれでログの行が出ることの自動試験。資格情報の文字列が出ないことの試験（`security-requirements.md` の NFR6.9） |
| NFR9.2 | 3 種類の拒否の件数を、メトリクスとして持つ（種類ごとのカウンタ）。接続元は件数の項目に含めず（ラベルの数が無制限に増えるのを避ける）、ログから調べる。メトリクスの収集と表示は、U1 の最小の範囲を超えない | メトリクスのカウンタが拒否ごとに増える自動試験 |
| NFR9.3 | U4 では警告（アラート）を設けない。429 の増加（総当たり、プロキシの設定の誤り）を知らせる警告は、本番運用で必要になったときに Operation で足す | 警告の定義が U4 の成果物に無いことの確認 |
| NFR9.4 | 参加の窓の見直しの根拠を残す。`rate_limited` の件数と接続元がログから調べられ、同じ NAT の背後での誤拒否（教室）や、プロキシの設定の誤り（全員が 1 つの接続元）を、ログの接続元の分布から見つけられる | 同じ接続元の 429 がログに並ぶことの試験。見直しの判断は Operation。ログに残る接続元の保持期間は Operation で定め、ゲームの保持期間（既定 30 日。U1 の NFR7.2）を超えない（`security-requirements.md` の NFR7.1） |
| NFR9.5 | 認可の拒否と無効な token は、操作の履歴（OperationLogEntry）に残さない。履歴は、成功した 7 種類の操作の監査の証跡のままにする（U3 の NFR9.1）。lastUsedAt の延長も履歴の対象にしない（BR17.2） | 拒否と延長の後に履歴を取得して、行が増えていないことの試験 |

## ログと履歴の使い分け（U4 の範囲）

| | 構造化ログ（U1 から引き継ぎ） | 操作の履歴（U3） |
| :--- | :--- | :--- |
| U4 の対象 | 無効な token、無効なコード、429、権限のない要求の拒否、lastUsedAt の書き込みの失敗 | 対象にしない |
| 目的 | 障害の調査、制限の見直し、総当たりやプロキシの設定の誤りの発見 | 誰が何をしたかの監査 |

## 引き継ぐもの

- 要求ごとの識別子、構造化ログの形式、ヘルスチェック（U1 の NFR3.5、NFR3.6）、資格情報を出さないこと（U1 の NFR6.4）はそのまま使う。要件の番号（NFRx.y）は、inception の NFRx を細分したもので、Unit ごとに独立している（U1、U3、U4 は同じ番号を別の要件に使う）。そのため、この文書群で U1 の要件を指すときは、必ず「U1 の」を付け、付けない番号は U4 自身の要件を指す。
- 指標の収集の基盤、アラートのしきい値、SLO、ダッシュボードは、後の Operation で定める。U4 は、拒否の件数のカウンタ（NFR9.2）以上の指標を新しく作らない。
