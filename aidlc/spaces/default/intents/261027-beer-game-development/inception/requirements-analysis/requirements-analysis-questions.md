# Requirements Analysis Questions

## Q1. [教材管理者] キット準拠の既定需要系列

ASM-01 の既定需要系列が未確定です。最初の実装でどう扱いますか？

- A. JSD 教材の運営条件を調査し、キット準拠系列を必須とする
- B. 進行役が任意の非負整数系列を登録する機能を先行し、既定系列は後続で追加する
- C. 一定需要 4 個の検証用プリセットを暫定採用する
- X. Other (please specify)

[Answer]: A. JSD 教材の運営条件を調査し、キット準拠系列を必須とする

## Q2. [進行役] 参加者の識別と復帰

専用ソフトなしで参加させつつ、再接続時に同じ参加者として復帰するため、初期スコープではどの識別方法を使いますか？

- A. 参加コードと browser に保存する復帰 token を使い、アカウント登録は不要とする
- B. email 等のアカウント登録と login を必須とする
- C. 表示名の再入力と進行役の再割当てだけで復帰する
- X. Other (please specify)

[Answer]: A. 参加コードと browser に保存する復帰 token を使い、アカウント登録は不要とする

## Q3. [進行役] データ保持期間

NFR-07 は保持期間を運営者が設定可能としています。初期値と削除時の挙動をどうしますか？

- A. デフォルト 90 日、設定可能、期限後にゲーム記録と復帰 token を自動削除する
- B. デフォルト 30 日、設定可能、期限後に自動削除する
- C. 自動削除は行わず、進行役の明示操作のみで削除する
- X. Other (please specify)

[Answer]: A. デフォルト 90 日、設定可能、期限後にゲーム記録と復帰 token を自動削除する

## Q4. [進行役] プレイ中の観察ビュー

観察者に公開できる情報が抽象的で、学習上の情報制約を壊す可能性があります。プレイ中の初期値はどれにしますか？

- A. 現在週、ステップ、役割ごとの入力完了状況のみ公開する
- B. A に加え、在庫・受注残・注文の合計値を公開する
- C. プレイ中の観察ビューは提供せず、終了後のみ全情報を開示する
- X. Other (please specify)

[Answer]: B. A に加え、在庫・受注残・注文の合計値を公開する

## Q5. [進行役] 結果データの出力形式

FR-14 の「再利用可能な形式」をテスト可能にするため、初期リリースで必須とする出力を指定しますか？

- A. CSV と JSON の両方を必須とする
- B. CSV のみを必須とし、JSON は後続とする
- C. JSON のみを必須とし、CSV は後続とする
- X. Other (please specify)

[Answer]: A. CSV と JSON の両方を必須とする
